# Task #105: Review cancelled audits across sessions

# Review cancelled audits across sessions

## What & Why
Let operators find and compare older cancelled or incomplete audits without relying on the browser's current execution pointer. This provides a durable review surface for retained proof and clearly distinguishes audits that are safe to retain from those that need a new run.

## Done looks like
- The dashboard lists recent cancelled and incomplete audits for the selected project.
- Operators can open an older audit and inspect its retained proof and disposition.
- The interface states whether a new run is recommended and exposes only safe recovery actions.
- The list refreshes when another session creates, cancels, or resolves an audit.
- Cross-project and cross-user audit data remains inaccessible.

## Out of scope
- Changing cancellation persistence or server-restart recovery behavior.
- Rebuilding the audit execution engine.
- Exposing raw provider errors, credentials, or unrestricted evidence.

## Steps
1. **Define the historical audit contract** — Reuse the existing execution status and recovery APIs to return an owner-scoped, project-scoped list of cancelled and incomplete audits with safe disposition metadata.
2. **Add the review list** — Build the dashboard surface for recent cancelled and incomplete audits, including loading, empty, unavailable, and permission-safe states.
3. **Connect historical detail** — Allow an operator to open a selected audit, inspect retained proof, understand its terminal status, and see whether a new run is recommended.
4. **Handle cross-session refresh** — Update the list when another session changes an audit while preventing stale results from replacing newer state.
5. **Add API and browser coverage** — Verify authorization, redaction, project isolation, cancelled and incomplete outcomes, historical selection, refresh behavior, and safe recovery actions.

# P7.5 — إجراء حوكمة مقترح لاستقلال العينات ومنشأ held-out

**الحالة:** تصميم إجراء فقط، 2026-09-30. وافق المستخدم على تصميمه، لا على
تعيين جهة أو تأهيل مصدر أو تشغيل حملة. يبقى قرار المالك
`NO_QUALIFIED_SOURCE` لكل من `independent-sampling-definition` و
`heldout-provenance`؛ شروط runtime السبعة `MISSING` بمراجع فارغة،
و`collectionAuthorized=false`، والاختيار `fixed_safe_probe`.

## الحدود وما يُعاد استخدامه

يخص هذا الإجراء تجربة Mission `runtime.start` المؤهلة من `stopped` إلى
`running` فقط. **عقد إثبات الادعاءين** وتفاصيل الرفض في
`docs/p75-sampling-heldout-source-contract.md`؛ **قرار المالك للادعاءات
السبعة** في `docs/p75-claim-authority-decision-record.md`؛ وبوابة القياس
والتعافي في `docs/agent-generalization-execution-plan.md` §42.8.
هذه الوثيقة ترتب المسؤوليات والزمن، ولا تنشئ عقد بيانات أو نسخة جديدة
من أي منها.

- Episode هو مصدر هوية تسجيل التجربة ونتيجتها، لا سلطة اختيار الوحدة أو
  تاريخ حجبها. لا يُنشأ تسجيل ثانٍ أو evaluator ثانٍ أو مصدر قبول موازٍ.
- حزمة الجاهزية الحالية تعيد تقريرًا تشخيصيًا للقراءة فقط. لا تتحول
  نتيجتها أو `thresholds_met_unverified` إلى موافقة بشرية أو إذن جمع.
- إثباتا الاختيار والحجب فئتا دليل مستقلتان منطقيًا، وليسا بالضرورة
  مخزنين أو جدولين. وسم `held_out` في strategy replay وCanonical Proof
  وshadow telemetry لا تحل محل أي منهما.
- هذا تصميم **مستقبلي** لا يجيز إعادة تصنيف outcomes أو fixtures سابقة
  بأثر رجعي. إذا غاب سجل استعمال قديم، فلا يستنتج عدم الاستعمال.

## 1. تعيين المسؤوليات قبل اختيار أي مصدر

يسمي المالك في سجل القرار جهة فعلية وأساس صلاحيتها ومدى صلاحيتها
لكل دور، أو يترك القرار `NO_QUALIFIED_SOURCE`. الأسماء أدناه **أدوار
مقترحة لا تعيينات حالية**:

| الدور | مسؤوليته المقترحة | الحد الذي لا يتجاوزه |
|---|---|---|
| مالك حوكمة P7.5 | اعتماد أساس سلطة الجهات وفصل الواجبات والاحتفاظ والتعارض، ثم اتخاذ قرار منفصل بشأن الجمع | لا يجعل قراره سجل المصدر دليلًا متحققًا تلقائيًا |
| مسؤول البروتوكول والتوقع | تثبيت فرضيات forecast/policy/probe/evaluator والنطاق قبل أي outcome، وإعلان نسخها وتغييراتها | لا يختار وحدات التقييم بعد رؤية النتائج أو يطّلع على held-out لضبط السياسة |
| مسؤول اختيار العينة | تحديد المجتمع ووحدة الاستقلال وإطار السحب وطريقته، وتوثيق الأهلية والاستبعاد وإعادة الاستخدام قبل النتيجة | لا يضبط forecast/policy/evaluator ولا ينتقي نجاحات بأثر رجعي |
| قيّم held-out | حفظ أصل الوحدات ونسخة العضوية وتقسيمها وسجل الاطلاع والاستخدام والتداخل | لا يستخدم نتائج التقييم في الضبط أو يصادق منفردًا على عدم استعماله الشخصي |
| مشغّل البيئة | إجراءات إعادة الضبط المحكومة والتحقق من حالة `stopped` ومراجعات المشروع والبيئة | لا يمنح الوكيل `stop` أو `restart` ولا يحوّل reset إلى عينة مستقلة |
| مراجع مستقل | تقييم الدليلين وملاءمة المقيم وبقية الشروط على حزمة ونطاق وإصدار محددين | لا يعتمد عملًا أصدره أو ضبطه بنفسه دون فصل مستقل موثق |
| مدقق خادمي مستقبلي | التحقق من مصدر الدليل وسلطته والربط والنطاق والزمن والتعارض وعرض مراجع الرفض | لا ينشئ سلطة أو يقبل `independent=true` أو `heldout=true` من caller |

قد تكون الجهة التنظيمية نفسها مرشحة لأكثر من دور، لكن لا يقبل دمج
الاختيار أو الحجب مع الضبط أو المصادقة الذاتية بلا فصل واجبات قابل
للتحقق وقرار مالك صريح. مصادقة Clerk تثبت هوية الجلسة فقط؛
`ADMIN_USER_IDS` وactor في Episode ليسا تفويض مراجعة P7.5.
إذا لم يحدد المالك جهة لها صلاحية إصدار دليل أحد الادعاءين، **يتوقف
الإجراء هنا** ولا يُكلف بناء writer أو verifier.

## 2. حزمة الالتزام السابقة لأول outcome

يراجع المالك والمراجع المقترحون معًا حدود سلطة المصدر، لكن مراجعتهم لا
تغير runtime حتى يوجد ربط وتحقق منفصلان. قبل أي سحب أو نتيجة:

1. **نطاق وبروتوكول مجمدان:** يحدد مسؤول البروتوكول المشروع ومراجعة
   المصدر والبيئة والهدف والفرضيات وforecast والقرار وprobe وطريقة ECE
   وbootstrap والـpartition وإصداراتها. يحتفظ مرجع مستقل بزمن الالتزام
   السابق للنتائج، والجهة المصدرة، وتاريخ الصلاحية وشروط الإبطال.
   الـhash يميز المحتوى ولا يثبت وحده متى جُمّد أو من أجازه.
2. **إطار سحب معلن مقدمًا:** يسجل مسؤول الاختيار مجتمع الاستدلال
   ووحدة الاستقلال، والمعايير وطريقة الاختيار وإصدارها، وكيف تُعامل
   الوحدات المتكررة أو المترابطة والاستبعادات والفشل. معرّف Mission
   لا يساوي وحدة مستقلة؛ لا تُنشأ إعادة تشغيل اصطناعية لبلوغ 30.
3. **حجب مثبت مقدمًا:** يسجل قيّم البيانات منشأ الوحدات ونسخة عضويتها
   وتقسيم التطوير/التقييم، وسجل الوصول والاستخدام في forecast وpolicy
   وprobe وevaluator. يتحقق من التداخل مع التطوير والتقييم السابق.
   غياب سجل الاستخدام أو ظهور نتائج قبل التجميد يمنع إثبات عدم التسرب.
4. **حفظ ومراجعة:** يقرر المالك أين تُحفظ مراجع الأدلة ومحتواها ومن
   يملك الاطلاع والتعديل والإبطال ومدة الاحتفاظ وآلية تدقيق الزمن.
   أحداث Episode تحذف تبعًا للمشروع؛ لا تُعتبر وحدها أرشيف حوكمة.
   لا يُختار مخزن أو سياسة IAM بهذه الوثيقة.

معرّف نطاق v1 الحالي يربط اسم partition وإصدارات السياسة ولا يربط
عضوية dataset جديدة. أي تقسيم أو سياسة مستقبلية معتمدة يحتاجان نسخة
ونطاقًا جديدين قبل أول outcome؛ لا تخلط بيانات مستقبلية مع v1 تحت
الاسم الثابت نفسه. لا يمكن إعادة إثبات ترتيب زمني غائب بتوقيع متأخر.

## 3. تسلسل كل وحدة محتملة — وصف لا إذن تشغيل

1. يصدر مسؤول الاختيار قرار السحب ونتيجة الأهلية والاستبعاد لكل
   وحدة مرشحة، مع كشف إعادة الاستخدام وربطها بإطارها وإصدار الطريقة
   قبل مشاهدة نتيجتها. تحفظ حالات الاستبعاد والفشل؛ لا تُزال لتحسين ECE.
2. يربط قيّم held-out الوحدة بعضوية النسخة المجمدة ويتحقق من سجل
   الوصول وعدم استعمال نتيجتها في الضبط قبل تسجيل التوقع. اختلاف
   العضوية أو التاريخ المجهول أو التداخل يبطل أهلية الوحدة، وقد يبطل
   النطاق كله بحسب قاعدة الإبطال المعتمدة مسبقًا.
3. يراجع مشغّل البيئة إجراء reset محكومًا وحالة `stopped` الفعلية
   ومراجعات المشروع والبيئة. تغير أي مراجعة ينشئ نطاقًا مختلفًا؛
   النجاح الذي ينقلها إلى `running` لا يُعاد تشغيله تلقائيًا كعينة ثانية.
4. **بعد تفويض جمع منفصل مستقبلًا فقط:** تحمل Mission المؤهلة هويات
   Goal والخطة والتنفيذ والمحاولة وEpisode، وتسجل توقعًا واحدًا ثم
   نتيجة واحدة في Episode القائم. تربط مراجع السحب والعضوية بالتسجيل
   دون نسخ سجل التجربة. لا يدخل endpoint العام لـ`runtime.start`
   أو strategy replay أو continuation في cohort v1.
5. يوقف التسجيل بلا نتيجة صالحة أو بتعارض/إلغاء تقييم نطاقه؛ لا
   ينتقي المراجع العينات المكتملة فقط. التعافي bounded ولا يعيد
   `runtime.start` أو يحذف التسجيل غير المحسوم.

## 4. المطابقة والمراجعة قبل أي ترقية

فقط بعد تفويض مصدر مؤهل ومطور للتحقق لاحقًا، يفحص مدقق يملكه الخادم
هوية المصدر وسلطته ومراجع النسخ والتوقيت والصلاحية والإبطال والتداخل،
ويربطها بالتسجيل والنتيجة وEpisode وبالنطاق الدقيق. داخل قاعدة
المشروع تُقرأ أحداث Episode في snapshot متسق؛ إذا كان مصدر الدليل
خارجيًا، فلا يُفترض أن معاملة قاعدة المشروع تغطيه: تُثبت نسخة
المصدر/موضعها الزمني وتُعاد المطابقة، ويُحجب الادعاء عند تغيرها أو
عدم إمكان التحقق منها.

| النتيجة | الحكم المقترح |
|---|---|
| لا مصدر أو سجل مطلوب | `MISSING`؛ لا تُستبدل بمراجعة بشرية مفترضة |
| مصدر حاضر بلا صلاحية جهة مثبتة أو بلا تاريخ استعمال قابل للتحقق | `UNVERIFIABLE` |
| مصدر أو دليل لا يغطي المراجعة أو الإصدار أو زمن النتيجة | `OUT_OF_SCOPE` |
| سجلان متعارضان، أو إعادة استخدام/تداخل غير محسوم | `CONFLICTING` |
| دليل محدد يستدعي قرار إنسان معيّن وآلية تحقق من مراجعته | `HUMAN_REVIEW_REQUIRED` فقط بعد وجود الربط، لا عند الغياب |
| تحقق خادمي كامل من ادعاء محدد ومصدر ذي سلطة | `SERVER_VERIFIED` لذلك الادعاء فقط، دون إذن جمع |

الانتهاء أو الإلغاء سببا حجب بحسب الحالة المناسبة، لا حالتان runtime
جديدتان. يراجع المراجع المستقل **الحزمة نفسها** وبصمة إصدار البروتوكول
والنطاق وزمن الصلاحية وحدود 30 Mission مستقلة وECE وحدها الأعلى
≤0.15، وأثر الفئات النادرة؛ هذه العتبات ليست بديلًا عن إثبات
الاستقلال أو ملاءمة المقيم. لا تُستعار عتبات strategy replay للترقية
اللاحقة. تبقى الشروط الخمسة الأخرى ضمن الادعاءات السبعة مستقلة.

عند انكشاف نتيجة قبل التجميد، أو تعديل forecast، أو تداخل، أو تغيير
عضوية، أو مراجعة مشروع/بيئة، أو سحب سلطة جهة، تُسجل علة الإبطال
ويُحجب النطاق المتأثر. لا تُمحى النتائج السابقة ولا يعاد احتساب
cohort باستبعاد العينات المزعجة. يلزم نطاق/سياسة ومستقبل held-out
مستقلان ومراجعة جديدة؛ لا اعتماد بأثر رجعي.

## قرار المالك التالي ومعيار خروج التصميم

هذا الإجراء جاهز **للمراجعة لا للتشغيل**. يسجل المالك لكل ادعاء:
الجهة المصدرة وأساس صلاحيتها وفصلها عن الضبط، مصدر سجل الاختيار
أو العضوية الفعلي وإصداره، ضمان الزمن والاستعمال والاحتفاظ، قاعدة
الإبطال والتعارض، والجهة المراجعة المستقلة. يمكن أن يظل القرار
`NO_QUALIFIED_SOURCE` إذا تعذر إثبات أي بند. تعيين المصدر وحده لا
يغير runtime؛ يتطلب تحققًا خادميًا وتفويض تنفيذ منفصلًا، ثم مراجعة
الشروط السبعة وموافقة جمع مستقلة. **لم تنشئ هذه الوثيقة مصدرًا
أو مراجعة معتمدة أو cohort أو writer أو verifier أو IAM أو تشغيلًا
أو نتيجة جديدة.**

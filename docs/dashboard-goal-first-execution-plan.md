# خطة التجربة العربية المتمحورة حول الهدف — EngineeringOS

> **تاريخ تحديث المستند:** 2026-10-13.
> **الحالة:** خطة تنفيذ مقترحة مبنية على قراءة الكود، لا تنفيذ لإعادة التصميم.
> طلب تحديث المستندات لا يصرح بتعديل الواجهة أو العقود أو البيانات أو تشغيل
> الاسترداد. لم تُشغّل اختبارات API أو متصفح أو دراسة مستخدمين لهذه المراجعة.
> أُضيف لاحقًا تنفيذ شريحة أساس ونتائج اختبارها في القسم 12؛ لا تُنسب تلك النتائج
> إلى المراجعة الأصلية أو إلى الحزم الباقية. هذا هو مرجع خطة UX الحالية؛ تحتفظ
> [المراجعة السابقة](dashboard-user-experience-review.md) بالتشخيص والسجل التاريخيين.
> لا تستبدل الخطة بوابات الإثبات أو خطة تعميم الوكيل أو مراحلها المعتمدة.

## 1. الهدف والنطاق

المستخدم المستهدف عربي وغير متخصص في البرمجة أو الهندسة. يستطيع وصف ما يريد
إنجازه، وفهم التقدم والقرار المطلوب والنتيجة وحدود التحقق دون تعلم أنواع
السجلات الداخلية. يدير الوكيل المراحل داخل نطاقه المسموح، ولا ينقلها كلها
إلى المستخدم ولا يكتسب إذنًا جديدًا من تبسيط العرض.

يشمل النطاق الصفحة الرئيسية، تسليم الهدف، بداية المشروع، ملخص العمل،
الكبسولة المشتركة، مراجعة القرارات، والتنقل والعربية والإتاحة.
يبقى المهندس قادرًا على فتح الأدلة والسجلات والمحاولات والتسليم.
ليس الهدف تغيير الألوان أولًا أو حذف الشاشات المتقدمة أو إعادة كتابة الصفحات.

## 2. مراتب الدليل في هذه الوثيقة

- **موجود في الكود:** وظيفة أو مسار أو شرط قرئ من المصدر.
- **تعارض مقروء:** عدم توافق بين أجزاء المصدر؛ يحتاج إثباتًا مستقلًا قبل الإصلاح.
- **مقترح:** عقد أو مكوّن أو سياسة تنفيذ مستقبلية، وليس واجهة موجودة.
- **يحتاج تحققًا:** سلوك تفاعلي أو أداء أو فهم مستخدم لم يُختبر في هذه المراجعة.

لا تُستخدم مراجع الأسطر التاريخية بوصفها عناوين ثابتة؛ الملفات والدوال أدناه
نقاط بحث. أسماء الحقول والمكونات المستقبلية وصفية وليست عقدًا منشورًا.

## 4. ثوابت لا يغيرها التصميم

1. القبول والأدلة والمحاولة والنسخة الحالية مصادر الحقيقة، لا نجاح المزود أو نسبة التقدم.
2. الإسقاط أو `PROVEN` المنسوخ لا يغني عن الارتباط الدائم المطلوب.
3. يظل معنى اكتمال Mission تابعًا للبوابة القائمة والخطة الفعالة.
4. نتيجة قديمة يمكن عرضها كتاريخ، ولا تُقدّم كنجاح التشغيل الحالي.
5. `allowedActions` وحدود الخادم لا تتوسع من النص أو المسودة أو فتح البطاقة.
6. الموافقة على Mission والخطة والتغييرات والتطبيق والحفظ والتسليم ليست إجراءً واحدًا.
7. لا إرسال تلقائي للمسودة ولا موافقة ضمنية من إنشاء مشروع.
8. الالتباس أو نقص البيانات يُعلن؛ لا يُحل بدمج تخميني أو نجاح أخضر.
9. كل بيانات الملخص والروابط مقيدة بملكية المستخدم والكيان المقصود.
10. لا تشغيل استرداد أو مصالحة أو إنشاء عمل لمجرد قراءة الملخص.

## 5. عقد عرض النتيجة المقترح

تفصل البيانات بين الحالة التشغيلية، وأساس التحقق، وارتباط النسخة والمحاولة،
وحالة التسليم، والقرار المطلوب. تظهر للمستخدم حالة رئيسية مع توضيح قصير؛
هذه أبعاد عرض لا آلة حالات جديدة مخزنة.

| أساس النتيجة | ما يراه المستخدم | ما لا يُستنتج |
|---|---|---|
| قبول مثبت ومطابق | اكتملت النتيجة ضمن الفحوص والنطاق المسجلين | سلامة كل المشروع أو أحدث نسخة تلقائيًا |
| فحص آلي محدود | نجح الفحص المسجل باسمه وحدوده | أن المشكلة أصلحت بالكامل |
| تحقق سجله المستخدم | سجّلت نجاح هذا الفحص | أنه اختبار آلي أو Canonical Proof |
| اكتمال بلا تفاصيل كافية | انتهت المهمة؛ تفاصيل التحقق غير متاحة | النجاح المثبت أو الفشل المؤكد |
| انقطاع أو إلغاء | توقف العمل، مع الاستئناف المسموح إن وجد | أن العمل مستمر |
| قبول غير مطلوب | انتهى الطلب دون تحقق هندسي مطلوب | منحه علامة تحقق هندسي |

الحالات الرئيسية: العمل مستمر، أحتاج قرارك، لم أتمكن من التأكد، اكتمل مع
التحقق المحدد؛ مع حالات طرفية محايدة للإلغاء والانتهاء غير الإثباتي.
تُعرض «لا توجد تفاصيل مسجلة» عند غياب البيانات. لا تُكتب «لم يُختبر»
إلا إذا كانت حدود التحقق المسجلة تدعمها. نجاح البناء لا يثبت تشغيل التطبيق،
ونسبة 100% لا تثبت قبول النتيجة.

`AiExecutionProjection.verification` وحده لا يحتوي كل أسماء الفحوص ونتائجها.
يُستفاد من نتائج التحقق وإيصالاتها الموجودة، وتُسقط الحقول المسموحة فقط؛
لا تُولد التفاصيل من مزود AI ولا تُكشف تشخيصات خام أو أجسام أدلة في الصفحة الرئيسية.

## 6. قراءة مساحة العمل المقترحة

المقترح الأولي توسيع استجابة Dashboard بإضافة ملخص متوافق مع الحقول التشغيلية
الحالية، لا تغيير معاني عداداتها. يبقى قرار الشكل النهائي تابعًا لإثبات
التغطية والتكلفة. لا جدول حالة جديد أو نسخة منفصلة من القبول.

### هوية عنصر العمل

- نوع الكيان الحقيقي ومعرّفه، المشروع، عنوان الهدف الآمن، آخر نشاط، وجهة الفتح.
- مرجع الخطة الفعالة والمحاولة الحالية عندما ينطبقان.
- الحالة المسجلة وملخص النتيجة وأساسها وحدود توفر بياناتها.
- هل يلزم قرار؟ ما نوعه وأين تُراجع نسخته الحالية؟
- نطاق الاستعلام وعلامة حداثته وتغطية المصادر وهل القائمة مختصرة.

### التجميع والتغطية

- تظهر Mission كطلب رئيسي عند وجود علاقة صريحة، وأطفالها داخل التفاصيل.
- Task أو Execution غير المرتبطين يبقيان مستقلين عند وجود عمل جدير بالمتابعة.
- يمنع التكرار بالعلاقات الدائمة لا العناوين أو نص الهدف.
- لا تدخل التحيات والمحادثة العامة ضمن عمل المشروع.
- تبدأ الخطة من `currentPlan.goalIds`؛ التاريخ لا يصبح جزءًا من الخطة الحالية.
- `revision_mismatch` يعني تعارضًا، لا عدم وجود عمل. لا تُختلق نسخة للسجلات القديمة.
- لا يُحسب عداد شامل من طول صفحة أو قائمة مختصرة.
- أقسام القرارات والعمل الجاري والنتائج الحديثة محدودة مستقلة حتى لا يخفي
  النشاط الكثير قرارًا ينتظر المستخدم.

### التكلفة واتساق القراءة

- جلب محدود ومجمع بدل استدعاء كل مشروع ثم كل مهمة وتنفيذ.
- تفاصيل السجلات والأدلة عند الفتح، لا أثناء تحميل الصفحة الرئيسية.
- لا إعادة استخدام MissionProjection الكامل لكل بطاقة؛ فهو يجلب تاريخًا
  متعدد الكيانات وأدلة مرشحي مهارات عند وجودها.
- يعاد استخدام منطق الإثبات القائم في قراءة متسقة محدودة، لا إنشاء مصنف قبول
  موازٍ أو إزالة أقفال بوابات القرار. تُثبت تكلفة هذا المسار قبل polling.
- إلى أن يُثبت مسار التحقق القرائي، يميز العرض الاكتمال المسجل من التحقق
  الحديث بدل ملء الفجوة بادعاء.

## 7. بداية الهدف وتسليم المسودات

| الحالة | المسار المقترح |
|---|---|
| لا مشروع | حفظ الهدف خلال إنشاء starter الحالي، ثم عرضه كمسودة في المشروع الناتج |
| مشروع واحد | إظهار اسم المشروع قبل الإرسال |
| عدة مشاريع | اختيار صريح للهدف القادم من الرئيسية، لا إرسال لأول مشروع |
| مشروع غير متاح | تنبيه بلا تبديل صامت إلى مشروع آخر |
| المساعد غير جاهز | سبب مفهوم وخطوة لازمة مع حفظ الهدف |
| نص أو مسودتان موجودتان | اختيار إدراج أو تجاهل صريح دون حذف مسودة غير مستخدمة |

ظرف المسودة المقترح يحدد الإصدار والمصدر والمشروع المقصود ووقت الإنشاء
وصلاحية السياق. لا يمثل أي منها سلطة خادمية.
الرابط الصريح يسبق الاختيار المحلي القديم. لا نغير الاختيار الافتراضي لكل
المساعد دون تمييز المسار القادم من الرئيسية.

تراعى المسودة عند إعادة التحميل وفشل التخزين وتغيير الحساب، ويُحدد سلوكها
بوضوح؛ لا يوعد باستمرار مسودة لم تُثبت استمراريتها. وصف starter الحالي
ومسودة الرئيسية مصدران مختلفان، فلا يُستهلك أحدهما بصمت لأن الآخر ملأ الإدخال.

## 8. القرارات والتحديث والتنقل

بطاقة القرار تفتح المراجعة في النسخة الأولى ولا توافق مباشرة. تعيد المراجعة
تحميل الخطة أو المقترح الحالي. تغير النسخة يجعل التأكيد القديم غير صالح؛
تظل مفاتيح منع التكرار والرفض الخادمي كما هي.

توحّد مفاتيح الاستعلام أو دالة التحديث بين الكبسولة وتفاصيل المهمة والملخص.
لا يثبت إبطال مفتاح التنفيذ العام تحديث المفتاح المخصص في Tasks تلقائيًا.
بعد الإجراء تحدث الأسطح المرتبطة فقط، دون محو مسودة المحادثة أو بثها.

يُفصل نطاق الاستعلام عن watermark المحتوى، وتغطى:
الحذف، القائمة الفارغة، تغيير المشروع والفلتر، دوران المحاولة، إعادة التخطيط،
وصول استجابة قديمة. `generatedAt` ليس نسخة محتوى. فشل التحديث لا يُعرض
كحالة قديمة مؤكدة وحديثة.

الواجهة العربية تضبط اللغة والاتجاه والمسافات والحدود واتجاه الهاتف.
تبقى الأكواد والمسارات والمعرّفات مقروءة باتجاه مناسب، وتُعرب أسماء الوصول.
تبقى حلول التركيز وEscape القائمة؛ لا يعاد بناؤها دون حاجة.

## 10. مصفوفة القبول والتحقق

| الحالة | الإثبات المطلوب |
|---|---|
| تنفيذ مكتمل وإثبات ناقص | لا علامة تحقق أو نجاح أوسع من البيانات |
| قبول لمحاولة قديمة أو ربط ملتبس | لا نجاح للتشغيل الحالي |
| Goal قديم نجح أو فشل | لا تلوث لحالة الخطة الفعالة |
| تغيير نسخة الخطة | رفض الموافقة القديمة؛ لا دمج للأهداف القديمة والجديدة |
| فحص وجود الملفات أو تحقق مستخدم | وصف ضيق وأساس تحقق صحيح |
| تطبيق بلا commit أو تسليم | عرض الخطوة المنجزة وما بقي، دون ادعاء تسليم |
| حذف أحدث عنصر أو قائمة فارغة | استبدال اللقطة القديمة لا استمرارها |
| تغيير المشروع أو الفلتر واستجابة متأخرة | لا تسرب لقطة النطاق السابق |
| طلبات مترابطة متعددة | لا تضخيم عداد العمل بتكرار الأب والأطفال |
| قرارات أكثر من حجم قائمة العمل | لا اختفاء القرار بسبب حد قسم آخر |
| مسودة وstarter أو إدخال قائم | لا استبدال أو حذف صامت أو إرسال تلقائي |
| صفر أو عدة مشاريع أو مزود غير جاهز | مسار قابل للفهم يحافظ على الهدف |
| مستخدم آخر أو وجهة غير متاحة | رفض الملكية أو إعلان عدم التوفر بلا وجهة بديلة صامتة |
| reload/reconnect وهاتف ولوحة مفاتيح | اتساق الحالة والقرار والروابط والتركيز |

التحقق المستقبلي: قواعد عرض مركزة، ثم API بقبول وأدلة دائمة لا إسقاطات
مصطنعة وحدها، ثم رحلة متصفح محددة للتغييرات الحرجة. تفصل fixtures التحقق
اليدوي عن إثبات AI. عند الفشل يوثق الفشل وحدوده قبل الإصلاح ويُثبت الإصلاح
باختبار مستقل. لا تقاس الجودة بعدد الاختبارات الناجحة.

دراسة الفهم مستقلة: هل يميز المستخدم التنفيذ من النتيجة المثبتة، ويعرف
المشروع والقرار والخطوة التالية؟ لا نجاح UI آليًا يثبت هذا الفهم، ولا توضع
عتبات تحسن رقمية دون خط أساس.

## 11. غير المشمول وحالة التسليم

- لا بوابة إثبات جديدة ولا جدول لحالات العرض ولا مخزن قبول موازٍ.
- لا موافقة مباشرة من بطاقة عامة ولا تحويل تلقائي لكل محادثة إلى Mission.
- لا تشغيل استردادات أو تغيير مراحل العمل المعتمدة أو إعادة إصدار إيصالات.
- لا استبدال stack أو قواعد ملكية أو إعادة كتابة الصفحات بالكامل.
- لا ادعاء بإجراء اختبار حي أو بتحقق الأداء والإتاحة والفهم ضمن تحديث المستند.

**حالة التنفيذ الحالية:** بدأت شريحة من A وتصحيح أولوية الحالة وجزء تأكيد
مشروع الهدف من D. لا تزال عقود النتيجة والملخص المجمّع وإعادة تنظيم الصفحة
والعربية الشاملة وبقية المسودات مقترحة؛ لا يعني تنفيذ الأساس إغلاق A–G.

استُكملت لاحقًا رحلة حفظ وتسليم المسودات من D كما يوثق القسم 13؛ لم يُنفذ
الملخص المجمّع أو إعادة تنظيم الصفحة الرئيسية أو العربية الشاملة ضمنها.

## 12. بدء التنفيذ: دليل الفشل قبل الإصلاح

بدأ تنفيذ الأساس بعد طلب البدء. أثبتت اختبارات مكونات مستقلة أن طلب قائمة
Tasks لا يحمل مشروعًا، وأن قائمة فارغة لا تستبدل القائمة المحتفظ بها،
وأن مراحل CHAT/INTAKE/READ/PLAN/BUILD/VALIDATE المحفوظة قد تخفي اكتمالًا
معروضًا من بيانات الإسقاط. هذه حدود مكونات وطلبات hooks؛ ليست دليل رحلة
حية أو إثباتًا لصلاحية قبول دائم. اختبار التحقق غير المتاح حافظ على الحجب.

الإصلاح لا يغير الخادم أو بوابات القبول، ولا يجعل إسقاط المكون Canonical Proof.

أثبت اختبار تسليم الهدف أن الإرسال لم يكن يتطلب تأكيد المشروع المختار
افتراضيًا. يضيف الإصلاح تأكيدًا محليًا لنطاق المشروع مع حارس داخل دالة
الإرسال، لا تعطيل زر فقط. لا يمنح التأكيد إذن Build أو موافقة على تغييرات.

### الشريحة المنفذة

- قائمة المهام ترسل مشروعًا مملوكًا ومفتاح استعلام يميز المشروع والفلاتر.
  لا تطلب قائمة بلا مشروع، وتتيح تغييره صراحة، ولا تختار بديلًا صامتًا
  لوجهة مشروع غير متاحة.
- الرابط إلى مهمة يحمّل المهمة المملوكة لتحديد مشروعها وإظهارها حتى لو كانت
  خارج صفحة القائمة الأولى. لا يُستخدم هذا لتعطيل ملكية API أو ربط القبول.
- نتيجة الاستعلام المعتمدة تستبدل القائمة عند الحذف أو الفراغ؛ أزيل احتفاظ
  Tasks بعلامة أحدث عنصر لأنها لا تمثل نسخة المجموعة. لم تُغيّر آلية
  watermark لبقية الصفحات ضمن هذه الشريحة.
- الاكتمال يتقدم على مرحلة تشغيل محفوظة، بعد حواجز الفشل والموافقة والإثبات
  الناقص والتسليم والمراجعة. هذا تصحيح عرض لا ترقية لقبول دائم.
- هدف الصفحة الرئيسية يتطلب تأكيد المشروع قبل الإرسال، ويعود الشرط عند
  تغيير المشروع. التأكيد لا يرسل الطلب، وحارس دالة الإرسال يغطي لوحة المفاتيح.
- إنشاء مهمة في مشروع آخر يختار مشروع المهمة الجديدة في القائمة بعد النجاح.

### دليل التحقق وحدوده

اجتازت اختبارات mission-state وExecutionProjectionPanel وTasks والمحادثة
المصادقة، وفحص TypeScript. تثبت ملكية نطاق العرض، وعزل مفاتيح المشروع،
واستبدال القائمة الفارغة، والوصول بالرابط، وأولوية الحالات والحفاظ على الحجب،
وعدم إرسال الهدف قبل التأكيد. لا تثبت Canonical Proof حقيقيًا أو استخدامًا
إنتاجيًا أو فهم مستخدم غير متخصص.

ظهر فشل لاختبار قديم لإرشاد حد الطلبات. أُعيد منفردًا وعلى نسخة مصدر معزولة
قبل التغييرات، وظهر الفشل نفسه؛ كان يتوقع نصًا سابقًا. صُحّحت assertions
لتثبت الإرشاد الحالي وغياب الإعادة التلقائية عند غياب وقت retry، مع الحفاظ
على فحوص التنقيح قبل إعادة فتح المحادثة وبعدها. لم يُغيّر سلوك المزود.

أعيد تشغيل Dashboard وظهر جاهزًا في سجل Vite. اللقطة غير المصادقة تعرض
صفحة الدخول العامة، فلا تُستخدم كإثبات للشاشات المحمية.

اجتاز فحص متصفح واحد في Firefox رحلة مصادقة ببيانات GET معزولة:
بقاء الهدف، منع الإرسال بـEnter قبل تأكيد المشروع، عدم إرسال الطلب عند
التأكيد، واشتراط تأكيد جديد عند تغيير المشروع. سجل اعتراض الطلبات صفر
طلبات AI. حملت طلبات المهام معرّفات المشاريع الصحيحة، واختفت صفوف المشروع
السابق عند الانتقال، ثم اختفت الصفوف بعد تحديث بقائمة فارغة.
لم تُنشأ سجلات backend ولم تحدث موافقة أو كتابة أو استرداد.

ظهرت مشكلة «Session history unavailable» وبعض أخطاء GET، ولم يكن المزود
متاحًا في المتصفح؛ لذلك لا يُنسب لهذا الفحص إثبات إرسال حي ناجح أو صحة
قائمة الجلسات. تغطي اختبارات المكونات الإرسال بعد التأكيد بمزود fixture.
لم ينفذ المتصفح حالة المشروع غير المتاح الاختيارية؛ يغطيها اختبار المكون.
هذه حدود دليل المتصفح وليست نجاحًا إنتاجيًا أو إغلاقًا لمشاكل غير مرتبطة.

### الباقي بعد الشريحة الأولى، قبل تنفيذ التكملة

عقد مسودة مُصدّر الإصدار، تعارض مسودتي الرئيسية وstarter، استمرار الهدف عبر
إنشاء مشروع وتغيير الحساب، وصف نتائج التحقق اليدوي، ملخص Missions/Tasks
المجمّع، العربية الشاملة، ودراسة الفهم ليست منجزة هنا. لم تُشغّل استردادات
أو تُعدّل قاعدة البيانات أو workflow الخادم ضمن هذا التنفيذ.

## 13. استكمال رحلة الهدف والمسودات

حدود ما قبل الإصلاح: كانت مسودة الرئيسية نصًا بلا حساب أو مشروع ويُحذف
عند فتح المساعد، ووصف starter مسارًا منفصلًا يُحذف عند القراءة. ملء الإدخال
من أحدهما قد يستهلك الآخر بلا استخدام. إنشاء المشروع كان يتجاوز فشل حفظ
الوصف إلى المساعد بصمت. هذه مشكلات حفظ وتسليم؛ لا تعني توسع صلاحيات الخادم.

التكملة توحد المصدرين في ظرف مصدّر الإصدار ومربوط بالحساب، بمعرّف مسودة
ومصدر ونطاق مشروع وعمر محدود. تُحفظ التعديلات، ولا تستهلك القراءة النص.
تعارض مصدرين أو نص موجود يحتاج اختيارًا صريحًا؛ يُحفظ النص المستبدل ولا
يُدمج مع الآخر. لا تُحمّل نصوص legacy غير المرتبطة بحساب إلى حساب حالي.
الحفظ في sessionStorage لهذا التبويب، وليس وعدًا بالاستمرار بعد إغلاقه.

عند غياب المشاريع ينتقل الهدف إلى starter الموجود، لا bootstrap جديد.
يُحفظ نصه ومفتاح طلب الإنشاء قبل بدء الطلب، ثم رقم العملية لاستئناف قراءتها
بعد إعادة التحميل دون بدء طلب جديد. تُربط المسودة بالمشروع الناتج قبل الانتقال
إلى المساعد. فشل الحفظ قبل الإنشاء يمنع بدء الطلب ويحفظ النص الظاهر؛ فشله
بعد الإنشاء لا يدّعي فشل الإنشاء ولا ينتقل بصمت، بل يتيح إعادة حفظ الارتباط.

تأكيد المشروع يبقى محليًا، منفصلًا عن الإرسال وعن Build/Apply. يحتفظ الإرسال
الصريح بنسخة قابلة للاختيار، موسومة «سبق بدء إرساله» لا «مقبول»؛ لا تُدرج أو
تُعاد تلقائيًا. تغيير الحساب يصفر النص الظاهر قبل الرسم ولا يستأنف عملية
حساب آخر. تغيير مشروع هدف محفوظ يبقي النص ويعيد طلب التأكيد.

### فشل التحقق وحدوده قبل تصحيحه

اجتازت اختبارات التخزين والمصدرين ومالك المسودة واستئناف الإنشاء، وفشل فحص
الأنواع في تضييق متغير التحميل الاختياري؛ صُحح الفرع دون تغيير العقد.
في فحص المحادثة فشلت أربع حالات متتابعة لأن تجهيز الاختبارات كان ينظف
localStorage فقط: افترض حذف مسودة sessionStorage عند القراءة. أظهرت
التوقعات نص حالة سابقة أو تعدد مسودات غير مقصود. صُحح تنظيف sessionStorage
بين الحالات، مع الحفاظ عليه داخل اختبار إعادة الفتح؛ لم يُضعف الحفظ.
تثبت اختبارات مستقلة عدم استبدال النص أو تسرب الحساب أو إرساله عند التحميل،
ومنع الكتابة عند تعذر التخزين، وثبات بوابة التأكيد أثناء إعادة تشغيل effects.

أثبت اختبار نتيجة متأخرة أن اكتمال طلب بعد إغلاق النموذج كان يوجّه إلى
المساعد رغم الإغلاق. حدوده callback الواجهة، لا تكرار mutation أو فشل
bootstrap نفسه. أضيف جيل محلي للنموذج: تُحفظ هوية العملية للمسودة الأصلية،
لكن لا تغير نتيجتها نموذجًا أُغلق أو بدأ طلبًا آخر، ولا تملك توجيه الحساب
بعد انتقاله. هذا سياج استمرارية واجهة لا lease أو صلاحية قبول جديدة.

### التحقق النهائي وحدوده

اجتازت اختبارات التخزين والاختيار واستعادة النص وعزل الحساب وانتهاء الصلاحية،
واختبارات Dashboard وstarter واستئناف العملية ونتيجتها المتأخرة، واختبارات
المحادثة الخاصة بالمسودات بعد إصلاح عزل التخزين، وفحص الأنواع. الحالات الأخرى
للمحادثة اجتازت التشغيل الأوسع السابق؛ لم يُعد تشغيلها بعد تصحيح تجهيز التخزين.

أكد فحص Firefox المسار: هدف بلا مشروع → نموذج starter بنص محفوظ → طلب
إنشاء واحد معترض → إعادة تحميل تستأنف قراءة العملية نفسها → ارتباط
بالمشروع الناتج → مسودة معدلة محفوظة بعد إعادة التحميل → اختيار بين نصين
مع إلغاء الاستبدال أو حفظ النص السابق. بقي عدد طلبات AI صفرًا. لم تُختبر
الهوية الثانية بالمتصفح؛ تغطيها اختبارات الحفظ والـhook وstarter المستقلة.

هذا تحقق واجهة ببيانات معزولة، لا إثبات لإنشاء مشروع حقيقي أو لقبول خادمي.
أبلغ المختبر أنه أصدر طلبي GET حقيقيين للوحة والمشاريع قبل تركيب fixtures،
ثم صار المسار الخاص بالمشاريع والإنشاء المعترض معزولًا. لذلك لم يُعتبر
التشغيل شهادة عزل شبكة كاملة ولم يُكرر؛ لم ينفذ bootstrap فعليًا أو إرسال AI.

بقي تعذر سجل الجلسات وأخطاء قراءة غير مرتبطة بالشريحة. أظهر سجل التطوير
خطأ إحصاءات بسبب عمود rate_limit_scope المفقود؛ لم تُطبق migration أو
تُعدّل قاعدة بيانات لمعالجة مشكلة خارج شريحة المسودات.

## 14. قراءة ملخص العمل والواجهة

استُكملت قراءة مستقلة محدودة للصفحة الرئيسية عبر GET
/api/dashboard/work-summary، مع بقاء عدادات Dashboard التشغيلية القديمة
على معناها. يعرض الملخص أقسام المراجعة والعمل الجاري والنتائج المسجلة
بحدود مستقلة، لا عددًا شاملًا مستنتجًا من طول القوائم.

كل مصدر مربوط بمالك المشروع، وتضيف Missions وExecutions هوية المستخدم.
يمنع التجميع التكرار بعلاقات Goal/Task/Execution الصريحة والخطة الفعالة،
لا بالعناوين أو نص الهدف. الأعمال التاريخية غير الحالية تبقى مستقلة
مع تنبيه يحتاج تفاصيل؛ التحيات والطلبات غير المصنفة لا تصير عملًا ضمنيًا.
عند تجاوز حد المصدر أو استبعاد تنفيذ أو نقص تغطية الأهداف يعلن الملخص
التغطية المحدودة، ولا يعرض فشل القراءة كأنه غياب للعمل.

القراءة snapshot متسقة repeatable-read/read-only، بحدود صفوف ووقت
استعلام ثابتة، دون dispatch أو مصالحة أو استرداد أو تحميل أجسام الأدلة
وcheckpoints ورموز الاستئناف. يستعمل إسقاط الخطة المشترك؛ لم يتغير منطق
بوابة اكتمال Mission. جميع النتائج recorded_only والتحقق not_revalidated.
روابط التفاصيل فقط، لا موافقة أو تنفيذ أو retry للعمل من بطاقة عامة.

يقرأ العميل باسم المستخدم الحالي، مع مفتاح cache خاص به وتحديث قراءة
محدود كل 30 ثانية. تستبدل الاستجابة الفارغة البطاقات السابقة، ولا تستعمل
علامة أحدث عنصر لترتيب المجموعات التي يمكن حذف عناصر منها. رابط Mission
الصريح يفتح المشروع والهدف المطلوبين، ويتوقف برسالة عند تعذر الوجهة.

### فشل التجهيز وحدوده قبل التصحيح

توقف التشغيل الأول للاختبارات المستقلة عند إدخال مشروع fixture بلا language،
وهو حقل إلزامي في schema. لم تصل هذه الحالات إلى قراءة الملخص، فلا تثبت
فشل عزل الملكية أو التجميع. صحح تجهيز المشروع بإعطاء لغة صريحة؛ لم يُغير
schema ولم يُضعف قيدًا. الاختبارات تستخدم cluster PostgreSQL مؤقتًا على
loopback مع DATABASE_URL صريح، وليس قاعدة التطوير أو الإنتاج.

أثبتت حالة إضافية أن تنفيذ Goal الحالي قد يكون paused بينما Goal ما زال
running، فيغيب Mission عن المراجعات رغم إخفاء التنفيذ الطفل لمنع التكرار.
حدود الفشل عرض المراجعة لا سلطة قبول أو صلاحية approval. صار القرار
الإرشادي يقرأ أحدث تنفيذ مملوك مرتبط بـGoal من الخطة الحالية، ولا يعيد
نتيجة paused قديمة إذا وجد تنفيذ أحدث. لا يغير Goal أو Mission أو تنفيذًا.

### إثبات السلوك وحدود التحقق

- اختبارات PostgreSQL المعزولة أثبتت ملكية جميع المصادر، وعدم الثقة بهوية
  query، واستبعاد أطفال الخطة الحالية دون حذف العمل التاريخي، ومنع مساواة
  hash رقمي بنسخة نصية، وعدم توريث تنفيذ paused قديم لمراجعة حالية.
  أثبتت أيضًا استقلال قسم المراجعة تحت كثرة العمل الجاري وحدود العينة،
  وتصنيف التنفيذ الحالي للـoperation بدل مراحل قديمة. انتهت هذه الحالات
  دون provider work، ثم أوقفت القاعدة المؤقتة وحذفتها.
- اجتازت فحوص الأنواع وفحوص مكونات الملخص والصفحة الرئيسية ووجهات Missions.
  أعيد تشغيل خدمتي API وDashboard؛ لم تُغير schema التطوير أو الإنتاج.
- تحقق المتصفح بعد Clerk programmatic handoff من GET حقيقي مصادق:
  /api/dashboard/work-summary أعاد HTTP 200 JSON للحساب الجديد، دون خطأ schema،
  مع not_revalidated وtotalCountAvailable=false والحدود المعلنة.
- البطاقات المعبأة وفحص رابط الهدف استعملا GET-only fixtures، لا بيانات
  عمل حقيقية. فتح الرابط المشروع والـMission المقصودين رغم وجود بديل أول
  في القوائم. اختلاف route لأحد fixtures عولج في اعتراض GET الخاص بالفحص
  فقط؛ ليس إصلاحًا أو تغييرًا في التطبيق.
- أثبتت إعادة القراءة الفارغة إزالة البطاقات السابقة، وأظهرت 503 حالة خطأ
  منفصلة عن الفراغ، وكرر «أعد القراءة» GET فقط. ثبت ظهور العرض عند desktop
  و390px دون horizontal overflow. عدد طلبات API المتغيرة من رحلة المتصفح
  صفر؛ لم تُرسل طلبات إنشاء عمل أو AI أو موافقة أو استئناف.

هذا إثبات قراءة وعرض وتوجيه فقط، لا Canonical Proof لإنجاز الأعمال
المعروضة ولا فحصًا لدقة تسليماتها. تحذير banner script ‏404/MIME في الفحص،
وأخطاء metrics/session-history السابقة، خارج هذه الشريحة ولم تُعالج
بتغيير قواعد بيانات أو تشغيل أعمال جديدة.

## 15. توحيد تفاصيل النتيجة والتحقق

القراءة الاستكشافية أكدت وجود MissionCapsule المشترك بالفعل، وأن إسقاط
Goal العام لا يحمل Canonical Proof حديثًا لإنجاز الهدف. إسقاط التنفيذ
يحمل حالة تحقق وverdict، لا أسماء فحوص ونتائج مفصلة. لذلك تستخدم الشريحة
المشتركة هذه البيانات كما هي، ولا تستنتج إثبات Goal من outcomeContract
القابل للتحرير أو من إثبات مرشح مهارة ذي نطاق مختلف.

### فشل موثق قبل التصحيح

كشف فحص الأنواع أن approval.status يستخدم PENDING بحروف كبيرة في العقد،
بينما قارنه مساعد العرض الجديد بقيمة pending. اختبارات تجهيز أولية
استخدمت صياغة صغيرة للحروف، ولم تغطِّ طلبًا منتهيًا مع PENDING حقيقي.
أُضيفت حالة مستقلة بصياغة العقد الحقيقي لإثبات أن مراجعة معلقة لا يجوز
أن تختفي خلف انتهاء التنفيذ. نطاق هذا الفشل نص العرض الجديد فقط:
قوائم الإجراءات والموافقات ومسارات الخادم لم تتغير.

### التصحيح والحدود المنفذة

طُبّعت حالة الموافقة للعرض فقط، وأثبت الاختبار المستقل ظهور المراجعة
مع PENDING الحقيقي رغم اكتمال التنفيذ. أثبتت حالة أخرى بقاء الشرح في
الكبسولة readOnly دون أزرار موافقة أو إيقاف أو استئناف أو تشغيل جديد،
حتى إن حمل الإسقاط قائمة إجراءات أوسع.

يعرض ResultDetailsSummary الشرح نفسه داخل الكبسولة الحالية وداخل تفاصيل
Goal المفتوحة: الحالة المسجلة، أساس العرض، حالة التحقق، حدود أسماء
الفحوص المتاحة، نطاق الخطة والمحاولة المسجلة عند توفرها. لا يستنتج نجاحًا
من النسبة أو PROVEN في checkpoint، ولا يصف غياب البيانات بأنه «لم يُختبر».
بيانات الخطة تحدد نطاق العرض فقط؛ لا تمنح قبولًا أو إثباتًا لإنجاز Goal.

بقيت بيانات السجل التقنية وحقولها متاحة، مع توضيح أنها بيانات مسجلة
لا إثبات حديث تلقائي. بقيت فحوص Tasks التفصيلية والإجراءات القائمة دون
حذف أو استبدال. لم تتغير API أو schema أو بوابات القبول أو منطق
mission-state أو أذونات الموافقة والاسترداد.

اجتازت فحوص العرض النقي والمكونات والكبسولة وMissions وثوابت mission-state،
ثم فحص الأنواع. تظهر تحذيرات act سابقة في اختبارات Missions؛ لم تفشل
الحالات ولم يُعدّل نطاق الاختبار أو يُضعف لإخفائها. أعيد تشغيل Dashboard
فقط، لأن الخادم وعقوده لم يتغيرا.

### فحص الصفحة المحمية

أثبت مرور متصفح محدود بعد تسجيل الدخول، باستخدام اعتراضات GET فقط،
أن بيانات acceptance/SUCCEEDED/PROVEN المصطنعة داخل outcomeContract لا
تظهر كإثبات حديث في الشرح المشترك للهدف. ظهر انتهاء مسجل ومحاولة مسجلة،
مع تمييز ارتباط الخطة من إثبات الإنجاز. وأظهر تغيير الخطة إلى
revision_mismatch التحذير الصحيح بدل احتساب الهدف ضمن إنجاز الخطة.

أظهرت كبسولة تنفيذ داخل Tasks الشرح نفسه رغم اكتمال السجل ونسبة 100٪
وحالة passed/PROVEN: لا قبول حديث مستنتج، ولا افتراض لسلامة المشروع أو
أحدث نسخة، ولا زعم بأن غياب أسماء الفحوص يعني عدم الاختبار. بقيت واجهة
Details/Logs وروابط القراءة، ولم تظهر أزرار تغيير العمل في الكبسولة ذات
قائمة الإجراءات الفارغة.

قياس عرض الهاتف 390px لم يظهر تجاوزًا أفقيًا. طلبات API المتغيرة الصادرة
من رحلة الفحص صفر، دون إنشاء أعمال أو فحوص يدوية أو طلبات AI. أخطاء
مطابقة مسارات fixtures الفرعية صححت في اعتراضات GET وحدها؛ لم تستلزم
تعديل التطبيق أو قاعدة البيانات. هذا الفحص يثبت العرض والتوجيه فقط،
ولا يثبت قبولًا هندسيًا أو نتائج الفحوص للأعمال المعروضة.

## 16. تعريب التنقل والعناوين الأساسية

### حدود الفحص الأول قبل التصحيح

بعد تعريب النصوص، فشلت اختبارات Landing القديمة التي تبحث عن عنوان وأزرار
وبطاقات إنجليزية، واختبارات Projects التي تبحث عن placeholder البحث وزر
الاكتشاف الإنجليزيين. الفشل موثق في محددات النص قبل تحديثها؛ لا يثبت عطلًا
في البحث أو التسجيل أو الاكتشاف. اجتازت فحوص التنقل والتركيز وTasks وMissions
في المرور نفسه. التصحيح المقصود تحديث النص المتوقع مع إبقاء assertions
الخاصة بالمسارات والتصفية وفتح النافذة وإغلاقها، لا حذف اختبارات السلوك.

### الشريحة المنفذة ودليلها

- تعريب تسميات التنقل وأسماء الوصول وعنوان الموقع الحالي، مع بقاء كل وجهات
  التنقل الأربع عشرة ومعرّفات المجموعات دون تغيير. استُبدلت توقعات عددية قديمة
  باختبار القائمة الدقيقة للمسارات، لا عداد غير مطابق للموجود.
- إعادة استخدام مجموعات الطي الحالية مع شرح عربي للأدوات المتقدمة؛ تفتح
  مجموعة الوجهة المباشرة تلقائيًا، ويظل المستخدم قادرًا على طيها.
- اتجاه الغلاف والقائمة عربي، وقائمة الهاتف تفتح من اليمين. ظل محتوى الصفحات
  القديم باتجاهه السابق لتجنب قلب مسارات وأكواد وأسطر تقنية لم تُراجع.
- تعريب رسالة البداية وأزرارها وعنوان الصفحة ووصفها، دون تغيير التسجيل أو
  تسجيل الدخول. تعريب عناوين المشاريع والمهام والأهداف والمحادثة العامة،
  والبحث والاكتشاف وإنشاء المشروع في رأس قائمة المشاريع.
- بقيت تفاصيل الرئيسية التقنية اختيارية كما كانت؛ لا حذف لسجلات أو
  إجراءات، ولا تغيير للخادم أو العقود أو بوابات الإثبات أو قاعدة البيانات.

أثبتت اختبارات المكونات بقاء روابط التسجيل ووجهات التنقل، وتصفية المشاريع
وفتح نافذة الاكتشاف وإغلاقها، وطي المجموعات حتى داخل الصفحة النشطة. أثبتت
حالات مستقلة حصر التركيز وإغلاق Escape واستعادته وتسليم تسجيل الخروج،
وعزل اتجاه المحتوى عن اتجاه التنقل. اجتاز فحص أنواع Dashboard وفحص diff.
اجتازت Tasks وMissions في المرور الأول دون تغييرات في قواعد حالاتها.

أُعيد تشغيل Dashboard، وأظهرت لقطة صفحة البداية غير المصادقة عند عرض
390px النص العربي والأزرار والبطاقات ضمن الشاشة. هذه اللقطة لا تختبر
الصفحات المحمية أو فهم المستخدم. ظهر خطأ مورد 502 مع عدم تشغيل API؛
شُغّلت خدمته القائمة دون تعديل كودها أو إعداداتها.
أظهرت الخدمة بعد البدء تحذيرات استرداد تلقائي لسجلات سابقة؛ لا يُنسب
تشغيلها إلى فحص ناجح للاسترداد، ولم تُشغّل طلبات استرداد يدوي ضمن الشريحة.

الشريحة ليست تعريبًا شاملًا للنماذج أو السجلات أو واجهات Clerk الداخلية،
ولا إثباتًا جديدًا للقبول أو التسليم. تظل دراسة الفهم وإكمال نصوص النماذج
وحالات التنفيذ الأساسية عملًا لاحقًا منفصلًا.

## 17. تعريب النماذج وحالات التنفيذ الأساسية

### الفحص الأول وحدود الفشل قبل التصحيح

بعد تعديل النصوص فقط اجتاز فحص أنواع Dashboard. أظهر المرور الأول فشل
توقعات نصية إنجليزية في اختبارات النماذج وحالات التنفيذ والاسترداد:
عناوين وأسماء أزرار الإغلاق والتعديل والحذف ونصوص الحالة. ظلت مفاتيح
حالات التنفيذ والإجراءات هي نفسها في فروق assertions التي ظهرت.
هذا دليل على توقعات لغة قديمة، لا دليل نجاح حي للإنشاء أو الاسترداد.
يُحدّث النص المتوقع دون حذف فحوص payload أو النطاق أو روابط القراءة،
وتضاف حالات مستقلة لمنع ترقية العرض العربي إلى صلاحية أو قبول.

أظهر اختبار جديد لنسبة 100٪ حالة «جاهز للمراجعة» بدل الانتهاء؛ احتفظ
fixture بفروق متاحة مع تحقق مجتاز، وهي أولوية صحيحة في منطق الحالة القائم.
لتثبت حالة الانتهاء المحددة دون خلطها بالمراجعة، تُزال الفروق من fixture
ذلك الاختبار فقط. لا يتغير ترتيب الحالات في المصدر لمعالجة هذا التوقع.

### التنفيذ والتحقق

- تعريب نماذج starter وMission وGoal وTask القائمة: العناوين والحقول
  والشرح والتحقق المحلي والأزرار والإغلاق وحالات الانتظار. يظهر Mission
  كهدف رئيسي، وGoal كخطوة داخله؛ لا تنشأ كيانات أو مسارات بديلة.
- تعريب نوافذ تعديل المهمة وتأكيد حذفها مع بقاء التحذير من الحذف النهائي.
  تبقى أخطاء الخادم كما وردت، مع عزل اتجاهها، دون ترجمة تخمينية.
- اتجاه النماذج العربية محلي، والنص الحر auto، وJSON والمعرّفات والتاريخ
  والمسارات والأكواد LTR. الإعدادات المتقدمة الموجودة اختيارية كما كانت.
- ربط مقترح التسليم، والموافقة عليه، وتجهيز هدف التطبيق، وتطبيق التغيير
  إجراءات منفصلة. النص العربي لا يمنح موافقة أو يَعِد بتطبيق فوري.
- تعريب حالات mission-state ونصوص الكبسولة المشتركة وعرض الاسترداد.
  مفاتيح الحالات وترتيب الشروط وallowedActions ومسارات الإجراءات لم تتغير.
  حالة الانتهاء وPROVEN ونسبة 100٪ تظل بيانات مسجلة، لا قبولًا حديثًا.
- عُرّبت أسماء المراحل المعروفة وحالات السجل، وبقيت القيم غير المعروفة
  ظاهرة دون تحويلها إلى نجاح. تفاصيل المزود والسجل ليست محتوى مترجمًا آليًا.

أثبتت اختبارات مستقلة ثبات مفاتيح الحالة عبر قوائم الإجراءات المسموحة،
ومنع أزرار التغيير في القراءة فقط، وفتح الأدلة دون تشغيل إجراء متغير،
وعزل المسارات باتجاه LTR. أثبتت حالة 100٪/passed/PROVEN أن نص الانتهاء
لا يدّعي قبولًا حديثًا، وأن غياب أسماء الفحوص ليس زعمًا بعدم الاختبار.
أثبتت النماذج أن إلغاء الإدخال لا يبدأ عملًا، وإعادة فتح المهمة تصفر مسودتها
المحلية كما كان، وJSON غير صالح يمنع إنشاء الهدف مع رسالة عربية.

اجتازت اختبارات الحفظ المتأخر للمشروع ونطاق payload والتعديل والحذف،
وحالات التنفيذ والاسترداد والمحادثة المصادقة. بعد المرور الشامل أُعيدت
الحالات التي فشلت بسبب توقعات لغة قديمة أو fixture المراجعة فقط؛ ظلت
الحالات المجتازة دون إعادة غير لازمة. اجتاز فحص الأنواع وdiff.
أعيد تشغيل Dashboard فقط؛ لم يتغير الخادم أو schema أو auth أو إعداداته.
تحذيرات الاسترداد التلقائي السابقة وbanner script ‏404/MIME خارج الشريحة.

### ملاحظة الهاتف قبل التصحيح

فحص Firefox المصادق عند 390×844 أثبت عرض النماذج والكبسولة، لكنه أظهر
أن توسيع الإعدادات المتقدمة في نافذة الهدف يترك أسفل زر الإلغاء خارج
اللقطة جزئيًا. الإلغاء نجح، فلا يُوصف هذا بفقدان بيانات أو تعطل الإجراء.
السبب حد ارتفاع ثابت لمنطقة الحقول دون حساب ارتفاع رأس وتذييل عربيين.
يُصحح بتقييد النافذة بارتفاع الشاشة ناقص حوافها، وتمرير الحقول داخل flex
محدود مع إبقاء الرأس والتذييل غير قابلين للانكماش؛ لا تغيير للحفظ والإغلاق.

### دليل المتصفح وحدوده

نجح المرور المحدود في Firefox بعد مصادقة Clerk باستخدام fixtures للقراءة
فقط. ظهرت نوافذ المشروع والهدف الرئيسي والمهمة باتجاه عربي مع حقول auto
وJSON ‏LTR، وبقيت قيم أولوية المهمة p0–p3 دون تغيير. نجح الإلغاء وإعادة
الفتح دون إرسال. ظهر ملخص التنفيذ من fixture مكتمل بنسبة 100٪ وpassed
وPROVEN مع موافقة معلقة، لكن العرض لم يمنح موافقة أو قبولًا حديثًا؛ ظهرت
مراجعة الأدلة وحدها حسب allowedActions، وبقي مسار src/App.tsx ‏LTR.
لم يظهر تجاوز أفقي عند 390px، ولم يُمرّر أي طلب API متغير.

هذا دليل عرض وإلغاء وتوجيه، لا إنشاء حي أو قبول هندسي أو اختبار استرداد.
لم يفحص المتصفح نافذة Goal الاختيارية أو تأكيد تعديل/حذف Task؛ تغطي
اختبارات المكونات تعديل المهمة وpayload الحذف وحدوده. ظهر banner
التطوير ‏404/MIME، وتجاوز reload واحد مهلة حدث load قبل أن تظهر الصفحة،
دون استثناء تشغيل للتطبيق.

بعد ملاحظة ارتفاع نافذة الهدف صُححت حدود flex والتمرير، وأثبت اختبار
مكوّن مستقل الحد المعتمد وإبقاء التذييل غير قابل للانكماش. اجتاز فحص
الأنواع وأعيد تشغيل Dashboard. لم يُعد فحص المتصفح أو قياس الهندسة
البصرية بعد هذا التصحيح البسيط، فلا يُنسب له screenshot محدث.

## 18. رسائل القرارات والأخطاء والفراغ

الشريحة التالية بعد طلب المتابعة تعالج رسائل العرض القائمة في المشاريع
والأهداف والمهام والمحادثة العامة، ونافذة تأكيد الموافقة/إعادة التخطيط.
لا تغيير لمسارات API أو payload أو التفويض أو رموز الحالة أو الاسترداد.
أسباب الخادم تبقى كما وردت مع اتجاه auto؛ النص العربي يشرح ما يمكن فعله،
ولا يحوّل فشل قراءة إلى دليل حذف أو فراغ أو فشل هندسي.

### الإخفاقات المثبتة قبل تصحيح توقعات الاختبارات

مرور المكونات الأول كشف أربع حالات Missions تتوقع إشعارات أو شرحًا
إنجليزيًا سابقًا، بينما ظهر النص العربي الجديد. بقيت assertions معرّفات
الطلبات والحجب والتحديث في مكانها؛ هذه إخفاقات توقع نص، وليست دليلًا على
إرسال مختلف أو قبول خادمي جديد. كشف اختبار النافذة المستقل أيضًا أن
عنوان الخطوة معروض مرتين عمدًا: في العنوان والشرح. بحثه المفرد أخفق؛
التصحيح المطلوب إثبات اتجاه النسختين، لا حذف إحداهما أو إضعاف فحص العزل.

أظهر المرور التالي توقعًا إنجليزيًا ثانيًا في اختبار الموافقة، واختبارًا
جديدًا لفراغ الفلتر يستخدم fixture ثابتًا لا يحاكي تصفية الخادم. القائمة
تعتمد تصفية status الخادمية؛ بقاء مهمة failed في mock استجابة running
ليس فشلًا في التصفية الحقيقية. يُصحح mock ليرجع لقطة فارغة لهذا الفلتر
مع إبقاء assertion مشروع الطلب وقيمة running، لا بإضافة تصفية موازية
أو تغيير المصدر ليلائم fixture.

### المنفذ ودليل التحقق

- رسائل البحث والفراغ وفشل التحميل وإعادة المحاولة في المشاريع والمهام
  والأهداف والمحادثة العامة عربية. فراغ العرض أو الفلتر لا يدّعي فراغ
  كل المشروع، وفشل تحميل المحادثات لا يظهر كقائمة فارغة.
- نافذة القرار عربية RTL، والعناوين الديناميكية معزولة بـbdi. تشرح

- رسائل انقطاع تحديثات المهمة والسجل وفراغ أدلتها وقرارات التحقق عربية.
  إعادة اتصال العرض لا تعني إعادة تنفيذ المهمة، وغياب تفاصيل التحقق
  لا يُوصف بأنه عدم إجراء اختبار.
- قرارات الفحوص اليدوية تُسمّى قرارات مسجلة، لا إثبات قبول شاملًا

- فشل إرسال المحادثة يوصف بعدم تأكيد القبول، لا برفض خادمي مثبت.
  استعادة المسودة القائمة لا ترسلها تلقائيًا. تأكيد حذف المحادثة
  يوضح أنه نهائي، والإلغاء لا يرسل طلب حذف.

## 19. تسميات الفلاتر والإجراءات الأساسية

تتابع الشريحة تعريب فلاتر حالة المهمة وأولويتها وقبولها، والبحث ومسحه،
والتحديث وانتظاره، وأزرار البدء وإعادة المحاولة والتراجع والاستئناف،
وعرض/طي التفاصيل وتبويبي التفاصيل والسجل. تبقى قيم option ومفاتيح
الإجراءات وطلبات المشروع وشروط إظهار/تعطيل الأزرار كما كانت. يمكن
لمجموعة الفلاتر الالتفاف دون قلب الصفحات التقنية كلها إلى RTL.

التحديث المشترك يقبل نصوص عرض اختيارية للانتظار وآخر تحديث؛ يحتفظ
بالنصوص الافتراضية القديمة للأسطح غير المعربة، ويعزل الوقت باتجاه LTR.
عُرب اسم اختيار مشروع الأهداف والمنطقة المحفوظة في المحادثة العامة.
عداد نتائج البحث يصف القائمة المحمّلة، لا العدد الكامل لكل مهام المشروع.

### إخفاق مستقل قبل تصحيح الاختبار

افترض اختبار جديد أن فلتر القبول يرسل requiresRecovery للخادم، لكن
الطلب الفعلي والقائم يحمل projectId/status/priority فقط. القبول فلتر
محلي على بيانات القائمة، بخلاف status/priority الخادميين. هذا إخفاق
في افتراض عقد الاختبار، لا دليلًا على تغير الطلب بسبب التعريب. يُصحح
الاختبار ليحفظ عقد الطلب نفسه ويثبت فراغ العرض المحلي، دون إضافة
معامل API أو نقل الفلتر إلى طبقة أخرى.

### التحقق وحدوده

اجتازت اختبارات المهام والأهداف والمحادثة العامة والتحديث المشترك.
أُعيد الاختبار المصحح وحده واجتاز. تثبت الحالات المستقلة بقاء p1
وقيم حالة التنفيذ الأصلية في طلب المشروع، وبقاء فلتر القبول محليًا،
ومسح البحث دون تشغيل مهمة. أثبت اختبار زر إعادة المحاولة إرسال معرّف
المهمة نفسه، وعدم استدعاء البدء أو التراجع أو فتح البطاقة بالضغط عليه.
أثبت التحديث العربي تعطيل الطلب الثاني أثناء الانتظار وعزل الوقت LTR.
بقيت اختبارات الاستئناف المسموح والمحجوب والتفاصيل والسجل قائمة، بعد
تحديث أسماء الوصول العربية دون حذف assertions السلوكية.

اجتاز فحص الأنواع وdiff. أعيد تشغيل Dashboard وحده وظهر جاهزًا. لم

## 20. مدخل مساعد المشروع ومحادثاته

الشريحة تعرب مدخل الرسالة وحالات التحميل والانتظار والإرسال، قائمة
محادثات المشروع واختيارها، وعناوين نقاط البداية وأوصافها. تبقى prompts
الجاهزة ومعرّفات analyze/review/tasks/workflow/probe ورسالة اختبار
القدرات الأصلية كما هي؛ نص العرض ليس مدخل توجيه جديدًا أو إذن تنفيذ.

### الإخفاقات المثبتة قبل التصحيح

مرور المكونات كشف بقايا محددات وتوقعات إنجليزية في اختبارات حقل الرسالة
وحالة المحادثة الجديدة ورسائلها غير المتاحة. تصحح محددات الحقل إلى
معرّفه المستقر مع اختبار مستقل لنصه العربي واتجاهه؛ لا تزال assertions
الإرسال والهوية والتأخير والحجب قائمة. لا يبرر هذا تغيير سلوك الاسترداد.

كشف اختبار الهاتف أيضًا أن ترجمة زر إغلاق اللوحة والخلفية إلى الاسم
نفسه جعلت الوصول بالاسم ملتبسًا. يُخصص للخلفية اسم «إغلاق قائمة
المحادثات من الخلفية»، مع إبقاء اسم زر اللوحة مستقلًا؛ لا يُحذف
أي زر ولا تتغير شروط الإغلاق أو استعادة التركيز.

### التحقق وحدوده

اجتاز مرور المحادثة المصادقة في اختبارات المكونات بعد تصحيح الحالات
المتأثرة وحدها، مع بقاء بقية الحالات المجتازة. يثبت ذلك استمرار حجب
الإرسال عند غياب المشروع أو تعذر تحميل الرسائل، وعزل المشروع والمحادثة
والتنفيذ، وعدم إدراج callbacks المتأخرة في محادثة جديدة. بقي حفظ
المسودات وتأكيد المشروع قبل إرسال هدف الرئيسية دون تغيير.

اختبار نقطة البداية يثبت أن فتح الإجراءات الإضافية لا يرسل طلبًا،
وأن زر القدرات العربي يرسل الرسالة الأصلية نفسها إلى المشروع نفسه.
يثبت أيضًا اسم حقل الرسالة العربي ونصه واتجاه auto، بدل الاعتماد على
العبارة الإنجليزية كمحدد في بقية الاختبارات. بقيت اختبارات لوحة
المحادثات على الهاتف والإغلاق والتركيز وحماية مدخلات المزود قائمة.
حُدّثت محددات أسماء الأزرار المتأثرة في رحلة E2E دون تشغيل الرحلة كاملة.

اجتاز فحص الأنواع وdiff، وأعيد تشغيل Dashboard فقط وظهر جاهزًا.
اللقطة غير المصادقة تؤكد تشغيل الصفحة العامة؛ لا تُنسب إلى شاشة
المساعد المحمية. لم يُرسل طلب AI حي ولم تتغير إعدادات أو بيانات

## 21. مراجعة الخطط والتغييرات ومراحل التسليم

عُرّبت واجهة خطة التنفيذ وأزرار الموافقة والرفض وبدء التنفيذ، مع بقاء
حالات الموافقة ونطاق الملفات وحداثة فحص المتصفح وشروط الحجب كما هي.
فتح الملفات والافتراضات إجراء عرض فقط. الموافقة تجهّز التنفيذ ولا تطبّق
الملفات. تبقى الفروق قابلة للمراجعة قبل التطبيق.

عُرّبت الإجراءات الأساسية للمقترح والتطبيق ومواءمة التعديل ورفضه،
ورسائل اعتماد Git ورفعه، واستئناف فحوص مساحة التسليم وإزالتها المؤكدة.
زر «الموافقة وتطبيق» ما زال يجمع الإجراءين عندما يتطلب المسار القائم
ذلك؛ لم يُقسّم أو يُمنح سلطة جديدة. اعتماد Git ورفعه إجراءان منفصلان،
ويظل التحذير بأن الإجراء الحالي قد يضم تعديلات محلية غير مرتبطة ظاهرًا.
اختيار مقطع من الفروق لا يعني قبولًا إثباتيًا ولا موافقة على الكتابة.

### الإخفاق المثبت قبل التصحيح

كشف مرور اختبارات المحادثة المصادقة توقعًا إنجليزيًا متبقيًا
`Approval unavailable` في حالة الخطة ذات النطاق غير المتحقق. ظهرت
الحالة العربية الصحيحة وبقي زر الموافقة غائبًا؛ الفشل في توقع نص
العرض، لا في بوابة الصلاحيات. يُصحّح النص المتوقع مع إثبات مستقل
لغياب بدء التنفيذ واستدعاء تطبيق الملفات.

### دليل التحقق وحدوده

اجتازت الحالات المصححة والممتدة في اختبارات المكونات المصادقة:
الخطة ذات النطاق غير المتحقق لا تعرض الموافقة أو بدء التنفيذ ولا
تستدعي تطبيق الملفات؛ فتح تفاصيل خطة صحيحة لا يستدعي التطبيق أو
اعتماد Git أو الرفع. اختيار مقاطع الفروق يمرر المقاطع المختارة فقط،
لا يمنحها علامة قبول إثباتي. بقيت هوية المشروع والمقترح في payload
التطبيق كما هي، وكذلك رسالة اعتماد Git الأصلية.

يظهر تحذير تعديلات Git غير المرتبطة، ويظل الاعتماد والرفع متوقفين
على الضغط الصريح على كل زر. اختبار تأكيد إزالة مساحة التسليم أثبت
أن فتح الحوار أو إلغاءه لا يرسل طلب الإزالة، وأن التأكيد يرسل الإجراء
القائم إلى العملية نفسها. هذه طلبات mocks؛ لم تُحذف مساحة حقيقية.

اجتاز فحص الأنواع وdiff، وأعيد تشغيل Dashboard وظهر جاهزًا. حُدّثت
محددات الإجراءات المتأثرة في رحلة E2E دون تشغيل الرحلة كاملة.
لقطة /dashboard/ai غير المصادقة تعرض الصفحة العامة، وليست دليلًا
بصريًا لمراجعة خطة مصادقة. لم يُجرَ تشغيل AI أو تطبيق أو اعتماد Git
أو رفع أو استرداد حي، ولم تتغير عقود الخادم أو إعداداته أو بياناته.
تبقى رسائل جاهزية المزود والتشخيصات والسجلات المتقدمة خارج هذه الشريحة،
ولا تُترجم بيانات الخادم الديناميكية تخمينيًا.

## 22. جاهزية المساعد وأسباب تعذّر الإرسال

تُعرض رسائل إعداد المساعد والانتظار وحجب الإرسال بالعربية، مع تمييز
عدم الإعداد، رفض الوصول، حد الاستخدام، وعدم التوفر المؤقت. يوضح
اسم زر الإرسال وحقل الرسالة سبب الحجب دون تغيير شروط التعطيل أو
حراس دالة الإرسال. عودة المزود لا تعيد إرسال المسودة تلقائيًا.

عُرّبت إرشادات إخفاق المزود الآمنة، مع إبقاء فئات الأخطاء وأكوادها
ومدد الانتظار ومعرّفات النماذج والمراجع كما هي. وجود إعداد صالح
ليس إثبات نجاح طلب حي؛ يعرض التنبيه «مُعدّ للإرسال»، لا نجاح تنفيذ.
رموز أسباب الجاهزية الخادمية تُعرض كرموز مسجلة، لا تُترجم تخمينيًا.
لا تُكشف تشخيصات المزود الخام ولا تُطلب مفاتيح وصول داخل المحادثة.

### الإخفاق المثبت قبل التصحيح

مرور اختبارات المحادثة المصادقة كشف توقعين إنجليزيين متبقيين
لإرشاد الإخفاق العام، في اختبار إخفاء تفريغ تقني داخلي واختبار
إعادة عرض إخفاق تحليل محفوظ. ظهر الإرشاد العربي بدل النص الإنجليزي؛
بقية فحوص التنقيح وعدم عرض اكتمال كاذب باقية. يصحح النص المتوقع
دون تعديل المحتوى المحفوظ أو التصنيف أو قبول التنفيذ.

اختبارا مدد الانتظار الموجبة لم يعرضا الرسائل لأن fixture استعلام
التاريخ يشترط تفعيل بيانات المقترح، وكان غير مفعّل في الاختبارين.
هذا إخفاق إعداد اختبار، لا فقدان رسائل أو خلل مهلة في التطبيق.
يُفعّل fixture التاريخ دون إضافة مقترح فعلي أو تغيير شرط تحميل حقيقي،
وتُصفّر حقول المهلة والنطاق بين الحالات لمنع تسرب بيانات الاختبار.

### دليل التحقق وحدوده

اجتازت اختبارات حفظ الرسالة وحجب الإرسال بالزر وEnter عند غياب
الإعداد أو تحميله أو رفض الوصول أو حد الاستخدام أو انقطاع المزود.
تثبت عودة الإعداد بقاء النص وإتاحة الإرسال الصريح دون إرسال تلقائي.
تثبت اختبارات المهلة عرض 2100 مللي ثانية كحد أدنى قدره 3 ثوانٍ،
مع التمييز بين حصة بيانات الوصول والحصة المشتركة. غياب موعد retry
يظل موضحًا بأنه لا يتيح إعادة محاولة تلقائية؛ لم تتغير آلية retry.

عُرّبت بطاقة إرشادات المزود المشتركة المستخدمة في المهام وسجل
تنفيذ سير العمل أيضًا. تعرض الأكواد والمراجع باتجاه LTR والإرشاد
الخادمي الديناميكي باتجاه auto دون تغييره أو تخمين ترجمته. اجتازت
اختبارات البطاقة ومستهلكيها حفظ المراجع وإخفاء التشخيصات الخام
والتعامل المحايد مع رمز حالة غير معروف. البطاقة إرشادية بلا أزرار
تشغيل؛ لا تمنح إذن استرداد أو كتابة.

اجتاز فحص الأنواع وdiff، وأعيد تشغيل Dashboard وظهر جاهزًا.
حُدّثت توقعات بطاقة المزود المتأثرة في رحلة E2E دون تشغيل الرحلة.
اللقطة غير المصادقة تعرض الصفحة العامة، لا واجهة المساعد المحمية.
لم تُشغّل طلبات AI حية أو يُغيّر إعداد مزود أو مفتاح أو بيانات خادم.

## 23. بطاقات مفاتيح المزود وإجراءات إعدادها

عُرّبت واجهة فتح إعدادات المساعد وبطاقات DeepSeek وGroq وGemini
وOpenRouter، بما فيها التحميل والحفظ والتغيير والإزالة ورسائل
النجاح والإخفاق. لكل حقل وزر اسم وصول عربي يحدد المزود، بما في ذلك
زر الإزالة الذي كان أيقونة بلا اسم. الحقول تبقى password واتجاهها LTR،
والبطاقات RTL. نهايات المفاتيح والروابط التقنية معزولة باتجاه مناسب.

لم تتغير hooks أو endpoints أو payloads أو شروط الانتظار أو حراس
الحفظ والإزالة. بقي إزالة الفراغات وفحص الحد الأدنى المحلي كما هما؛
ذلك لا يثبت صلاحية المفتاح لدى المزود. إزالة المفتاح الشخصي لا تعني
حذف مفتاح الخادم، ولا يعني توفر إعداد افتراضي ضمان وجوده.

سبب استخدام الإجابة البديلة، ويذكر قبول التشغيل واكتمال أدلته فقط
عندما يعيد العقد القيمتين الصريحتين المناسبتين. عُرضت المتابعة

أو يطلق إعادة محاولة أو تغييرًا. بقي طلب التشخيص مرتبطًا بالرسالة
والتشغيل والمشروع والجلسة المحددة، وأُضيف طلب الشرح العربي مع حفظ
التوافق مع الصياغة الإنجليزية السابقة.

## 28. اختيار نطاق الهدف قبل فتح مساعد المشروع

### الفشل وحدوده قبل الإصلاح

عند غياب اسم مشروع مطابق أو وجود أكثر من اسم محتمل، كان خيار «داخل مشروع»

المستخدم في سياق المسودة. هذا خطر مستنتج من مسار الكود واختبار المكوّن،
وليس تقريرًا عن إرسال حي أو تغيّر بيانات.

في أول تشغيل للاختبار المركز بعد تغيير النص، اجتازت 11 من 13 حالة. توقفت

قبل فحص التوجيه إلى مشروع محدد. اجتاز فحص الأنواع؛ لا تثبت هاتان الحالتان
خللًا في منطق اختيار النطاق.

### التصحيح

تعرض متابعة الهدف الآن اختيار نطاق صريحًا قبل حفظ المسودة أو التنقل:

- الاسم المطابق يظهر اقتراحًا لا اختيارًا تلقائيًا؛ ويمكن للمستخدم اختيار
  الاقتراح أو مشروع آخر بالمعرّف المحدد.
- عند غياب تطابق واضح أو تعدد الاحتمالات لا يُفتح مساعد المشروع دون اختيار
  مشروع بعينه؛ يرفض الحارس أيضًا معرّفًا مفقودًا أو لم يعد ضمن القائمة.
- أثناء التحميل أو فشل قراءة المشاريع لا يوجد مسار إلى مساعد المشروع؛ يمكن
  إعادة القراءة أو اختيار سؤال عام صراحةً بلا سياق ملفات.
- عند عدم وجود مشاريع يبقى مسار إنشاء المشروع الحالي هو الاختيار.
- تظل المسودة غير مرسلة، ويطلب مساعد المشروع تأكيد النطاق قبل الإرسال؛ لم
  تتغير API أو التخزين أو حدود الموافقة.

### دليل التحقق وحدوده

بعد تحديث توقعي النص المتأثرين، اجتازت حالات الرئيسية المركزة 13/13 وفحص
الأنواع و`git diff --check`. تثبت الحالات عدم إنشاء مسودة أو تنقل قبل الاختيار،
وربط المسودة بمعرّف المشروع المحدد في الاسم المطابق والاختيار اليدوي،
والتعامل الصريح مع مشروعين أو مشروع وحيد غير مذكور، والتحويل العام المختار،
والإنشاء عند غياب المشاريع، والحجب عند فشل تحميل القائمة. لم ترسل الاختبارات
طلبات AI حية ولم تغيّر بيانات الخادم. لا تثبت هذه الحالات وحدها فهم المستخدم
أو رحلة متصفح مصادقًا عليها.

## 29. المسودات القديمة بلا مشروع صريح

### الإخفاق وحدوده قبل التصحيح

### التصحيح والتحقق

وتأكيد المشروع محجوبين إلى أن يختار المستخدم نطاقًا. إذا حملت المسودة أو
الرابط مشروعًا صريحًا، يبقى ذلك المشروع هو المختار ويتطلب تأكيد المسودة

## 30. التنقل بين السؤال العام والعمل داخل مشروع

أُضيف انتقال مشترك في رأسي المحادثتين دون دمج واجهتي API أو سجلّيهما:

- من المحادثة العامة يختار المستخدم مشروعًا من القائمة الفعلية؛ لا يُختار
  المشروع الأول تلقائيًا. التحميل والفشل والقائمة الفارغة لها حالات واضحة.
- رابط العودة إلى العام يحتفظ بمعرّف محادثته العامة فقط؛ لا يمرر `projectId`
  أو معرّف جلسة المشروع إلى مساحة العام.
- النص العادي غير المرسل يُحفظ داخل التبويب ويرتبط بالحساب والمساحة والمشروع
  والمحادثة المحددة. تبديل المحادثة أو المشروع يحفظ النص في سياقه السابق
  ويفصل خانة الكتابة عن السياق الجديد. عند العودة يظهر النص قابلًا للتحرير،
  ولا يُرسل تلقائيًا.
- تبقى مسودات الأهداف المحفوظة في مسارها المنفصل؛ لا تتحول إلى نص عام أو مشروع.
  إذا تعذر حفظ نص عادي قبل الانتقال، يُطلب تأكيد صريح بدل فقدانه بصمت.

والبناء و`git diff --check`. لم تتغير واجهات API أو قاعدة البيانات. لقطة
المعاينة ما زالت صفحة الدخول العامة، لذا لم تُفحص واجهات المحادثة لمستخدم
مسجل بصريًا.

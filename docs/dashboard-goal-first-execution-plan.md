# خطة التجربة العربية المتمحورة حول الهدف — EngineeringOS

> **تاريخ تحديث المستند:** 2026-10-13.
> **الحالة:** خطة تنفيذ مقترحة مبنية على قراءة الكود، لا تنفيذ لإعادة التصميم.
> طلب تحديث المستندات لا يصرح بتعديل الواجهة أو العقود أو البيانات أو تشغيل
> الاسترداد. لم تُشغّل اختبارات API أو متصفح أو دراسة مستخدمين لهذه المراجعة.
> أُضيف لاحقًا تنفيذ شريحة أساس ونتائج اختبارها في القسم 12؛ لا تُنسب تلك النتائج
> إلى المراجعة الأصلية أو إلى الحزم الباقية. هذا هو مرجع خطة UX الحالية؛ تحتفظ
> [المراجعة السابقة](dashboard-user-experience-review.md) بالتشخيص والسجل التاريخيين.
> لا تستبدل الخطة بوابات الإثبات أو خطة تعميم الوكيل أو مراحلها المعتمدة.

## 1. الهدف والنطاق

المستخدم المستهدف عربي وغير متخصص في البرمجة أو الهندسة. يستطيع وصف ما يريد
إنجازه، وفهم التقدم والقرار المطلوب والنتيجة وحدود التحقق دون تعلم أنواع
السجلات الداخلية. يدير الوكيل المراحل داخل نطاقه المسموح، ولا ينقلها كلها
إلى المستخدم ولا يكتسب إذنًا جديدًا من تبسيط العرض.

يشمل النطاق الصفحة الرئيسية، تسليم الهدف، بداية المشروع، ملخص العمل،
الكبسولة المشتركة، مراجعة القرارات، والتنقل والعربية والإتاحة.
يبقى المهندس قادرًا على فتح الأدلة والسجلات والمحاولات والتسليم.
ليس الهدف تغيير الألوان أولًا أو حذف الشاشات المتقدمة أو إعادة كتابة الصفحات.

## 2. مراتب الدليل في هذه الوثيقة

- **موجود في الكود:** وظيفة أو مسار أو شرط قرئ من المصدر.
- **تعارض مقروء:** عدم توافق بين أجزاء المصدر؛ يحتاج إثباتًا مستقلًا قبل الإصلاح.
- **مقترح:** عقد أو مكوّن أو سياسة تنفيذ مستقبلية، وليس واجهة موجودة.
- **يحتاج تحققًا:** سلوك تفاعلي أو أداء أو فهم مستخدم لم يُختبر في هذه المراجعة.

لا تُستخدم مراجع الأسطر التاريخية بوصفها عناوين ثابتة؛ الملفات والدوال أدناه
نقاط بحث. أسماء الحقول والمكونات المستقبلية وصفية وليست عقدًا منشورًا.

## 4. ثوابت لا يغيرها التصميم

1. القبول والأدلة والمحاولة والنسخة الحالية مصادر الحقيقة، لا نجاح المزود أو نسبة التقدم.
2. الإسقاط أو `PROVEN` المنسوخ لا يغني عن الارتباط الدائم المطلوب.
3. يظل معنى اكتمال Mission تابعًا للبوابة القائمة والخطة الفعالة.
4. نتيجة قديمة يمكن عرضها كتاريخ، ولا تُقدّم كنجاح التشغيل الحالي.
5. `allowedActions` وحدود الخادم لا تتوسع من النص أو المسودة أو فتح البطاقة.
6. الموافقة على Mission والخطة والتغييرات والتطبيق والحفظ والتسليم ليست إجراءً واحدًا.
7. لا إرسال تلقائي للمسودة ولا موافقة ضمنية من إنشاء مشروع.
8. الالتباس أو نقص البيانات يُعلن؛ لا يُحل بدمج تخميني أو نجاح أخضر.
9. كل بيانات الملخص والروابط مقيدة بملكية المستخدم والكيان المقصود.
10. لا تشغيل استرداد أو مصالحة أو إنشاء عمل لمجرد قراءة الملخص.

## 5. عقد عرض النتيجة المقترح

تفصل البيانات بين الحالة التشغيلية، وأساس التحقق، وارتباط النسخة والمحاولة،
وحالة التسليم، والقرار المطلوب. تظهر للمستخدم حالة رئيسية مع توضيح قصير؛
هذه أبعاد عرض لا آلة حالات جديدة مخزنة.

| أساس النتيجة | ما يراه المستخدم | ما لا يُستنتج |
|---|---|---|
| قبول مثبت ومطابق | اكتملت النتيجة ضمن الفحوص والنطاق المسجلين | سلامة كل المشروع أو أحدث نسخة تلقائيًا |
| فحص آلي محدود | نجح الفحص المسجل باسمه وحدوده | أن المشكلة أصلحت بالكامل |
| تحقق سجله المستخدم | سجّلت نجاح هذا الفحص | أنه اختبار آلي أو Canonical Proof |
| اكتمال بلا تفاصيل كافية | انتهت المهمة؛ تفاصيل التحقق غير متاحة | النجاح المثبت أو الفشل المؤكد |
| انقطاع أو إلغاء | توقف العمل، مع الاستئناف المسموح إن وجد | أن العمل مستمر |
| قبول غير مطلوب | انتهى الطلب دون تحقق هندسي مطلوب | منحه علامة تحقق هندسي |

الحالات الرئيسية: العمل مستمر، أحتاج قرارك، لم أتمكن من التأكد، اكتمل مع
التحقق المحدد؛ مع حالات طرفية محايدة للإلغاء والانتهاء غير الإثباتي.
تُعرض «لا توجد تفاصيل مسجلة» عند غياب البيانات. لا تُكتب «لم يُختبر»
إلا إذا كانت حدود التحقق المسجلة تدعمها. نجاح البناء لا يثبت تشغيل التطبيق،
ونسبة 100% لا تثبت قبول النتيجة.

`AiExecutionProjection.verification` وحده لا يحتوي كل أسماء الفحوص ونتائجها.
يُستفاد من نتائج التحقق وإيصالاتها الموجودة، وتُسقط الحقول المسموحة فقط؛
لا تُولد التفاصيل من مزود AI ولا تُكشف تشخيصات خام أو أجسام أدلة في الصفحة الرئيسية.

## 6. قراءة مساحة العمل المقترحة

المقترح الأولي توسيع استجابة Dashboard بإضافة ملخص متوافق مع الحقول التشغيلية
الحالية، لا تغيير معاني عداداتها. يبقى قرار الشكل النهائي تابعًا لإثبات
التغطية والتكلفة. لا جدول حالة جديد أو نسخة منفصلة من القبول.

### هوية عنصر العمل

- نوع الكيان الحقيقي ومعرّفه، المشروع، عنوان الهدف الآمن، آخر نشاط، وجهة الفتح.
- مرجع الخطة الفعالة والمحاولة الحالية عندما ينطبقان.
- الحالة المسجلة وملخص النتيجة وأساسها وحدود توفر بياناتها.
- هل يلزم قرار؟ ما نوعه وأين تُراجع نسخته الحالية؟
- نطاق الاستعلام وعلامة حداثته وتغطية المصادر وهل القائمة مختصرة.

### التجميع والتغطية

- تظهر Mission كطلب رئيسي عند وجود علاقة صريحة، وأطفالها داخل التفاصيل.
- Task أو Execution غير المرتبطين يبقيان مستقلين عند وجود عمل جدير بالمتابعة.
- يمنع التكرار بالعلاقات الدائمة لا العناوين أو نص الهدف.
- لا تدخل التحيات والمحادثة العامة ضمن عمل المشروع.
- تبدأ الخطة من `currentPlan.goalIds`؛ التاريخ لا يصبح جزءًا من الخطة الحالية.
- `revision_mismatch` يعني تعارضًا، لا عدم وجود عمل. لا تُختلق نسخة للسجلات القديمة.
- لا يُحسب عداد شامل من طول صفحة أو قائمة مختصرة.
- أقسام القرارات والعمل الجاري والنتائج الحديثة محدودة مستقلة حتى لا يخفي
  النشاط الكثير قرارًا ينتظر المستخدم.

### التكلفة واتساق القراءة

- جلب محدود ومجمع بدل استدعاء كل مشروع ثم كل مهمة وتنفيذ.
- تفاصيل السجلات والأدلة عند الفتح، لا أثناء تحميل الصفحة الرئيسية.
- لا إعادة استخدام MissionProjection الكامل لكل بطاقة؛ فهو يجلب تاريخًا
  متعدد الكيانات وأدلة مرشحي مهارات عند وجودها.
- يعاد استخدام منطق الإثبات القائم في قراءة متسقة محدودة، لا إنشاء مصنف قبول
  موازٍ أو إزالة أقفال بوابات القرار. تُثبت تكلفة هذا المسار قبل polling.
- إلى أن يُثبت مسار التحقق القرائي، يميز العرض الاكتمال المسجل من التحقق
  الحديث بدل ملء الفجوة بادعاء.

## 7. بداية الهدف وتسليم المسودات

| الحالة | المسار المقترح |
|---|---|
| لا مشروع | حفظ الهدف خلال إنشاء starter الحالي، ثم عرضه كمسودة في المشروع الناتج |
| مشروع واحد | إظهار اسم المشروع قبل الإرسال |
| عدة مشاريع | اختيار صريح للهدف القادم من الرئيسية، لا إرسال لأول مشروع |
| مشروع غير متاح | تنبيه بلا تبديل صامت إلى مشروع آخر |
| المساعد غير جاهز | سبب مفهوم وخطوة لازمة مع حفظ الهدف |
| نص أو مسودتان موجودتان | اختيار إدراج أو تجاهل صريح دون حذف مسودة غير مستخدمة |

ظرف المسودة المقترح يحدد الإصدار والمصدر والمشروع المقصود ووقت الإنشاء
وصلاحية السياق. لا يمثل أي منها سلطة خادمية.
الرابط الصريح يسبق الاختيار المحلي القديم. لا نغير الاختيار الافتراضي لكل
المساعد دون تمييز المسار القادم من الرئيسية.

تراعى المسودة عند إعادة التحميل وفشل التخزين وتغيير الحساب، ويُحدد سلوكها
بوضوح؛ لا يوعد باستمرار مسودة لم تُثبت استمراريتها. وصف starter الحالي
ومسودة الرئيسية مصدران مختلفان، فلا يُستهلك أحدهما بصمت لأن الآخر ملأ الإدخال.

## 8. القرارات والتحديث والتنقل

بطاقة القرار تفتح المراجعة في النسخة الأولى ولا توافق مباشرة. تعيد المراجعة
تحميل الخطة أو المقترح الحالي. تغير النسخة يجعل التأكيد القديم غير صالح؛
تظل مفاتيح منع التكرار والرفض الخادمي كما هي.

توحّد مفاتيح الاستعلام أو دالة التحديث بين الكبسولة وتفاصيل المهمة والملخص.
لا يثبت إبطال مفتاح التنفيذ العام تحديث المفتاح المخصص في Tasks تلقائيًا.
بعد الإجراء تحدث الأسطح المرتبطة فقط، دون محو مسودة المحادثة أو بثها.

يُفصل نطاق الاستعلام عن watermark المحتوى، وتغطى:
الحذف، القائمة الفارغة، تغيير المشروع والفلتر، دوران المحاولة، إعادة التخطيط،
وصول استجابة قديمة. `generatedAt` ليس نسخة محتوى. فشل التحديث لا يُعرض
كحالة قديمة مؤكدة وحديثة.

الواجهة العربية تضبط اللغة والاتجاه والمسافات والحدود واتجاه الهاتف.
تبقى الأكواد والمسارات والمعرّفات مقروءة باتجاه مناسب، وتُعرب أسماء الوصول.
تبقى حلول التركيز وEscape القائمة؛ لا يعاد بناؤها دون حاجة.

## 10. مصفوفة القبول والتحقق

| الحالة | الإثبات المطلوب |
|---|---|
| تنفيذ مكتمل وإثبات ناقص | لا علامة تحقق أو نجاح أوسع من البيانات |
| قبول لمحاولة قديمة أو ربط ملتبس | لا نجاح للتشغيل الحالي |
| Goal قديم نجح أو فشل | لا تلوث لحالة الخطة الفعالة |
| تغيير نسخة الخطة | رفض الموافقة القديمة؛ لا دمج للأهداف القديمة والجديدة |
| فحص وجود الملفات أو تحقق مستخدم | وصف ضيق وأساس تحقق صحيح |
| تطبيق بلا commit أو تسليم | عرض الخطوة المنجزة وما بقي، دون ادعاء تسليم |
| حذف أحدث عنصر أو قائمة فارغة | استبدال اللقطة القديمة لا استمرارها |
| تغيير المشروع أو الفلتر واستجابة متأخرة | لا تسرب لقطة النطاق السابق |
| طلبات مترابطة متعددة | لا تضخيم عداد العمل بتكرار الأب والأطفال |
| قرارات أكثر من حجم قائمة العمل | لا اختفاء القرار بسبب حد قسم آخر |
| مسودة وstarter أو إدخال قائم | لا استبدال أو حذف صامت أو إرسال تلقائي |
| صفر أو عدة مشاريع أو مزود غير جاهز | مسار قابل للفهم يحافظ على الهدف |
| مستخدم آخر أو وجهة غير متاحة | رفض الملكية أو إعلان عدم التوفر بلا وجهة بديلة صامتة |
| reload/reconnect وهاتف ولوحة مفاتيح | اتساق الحالة والقرار والروابط والتركيز |

التحقق المستقبلي: قواعد عرض مركزة، ثم API بقبول وأدلة دائمة لا إسقاطات
مصطنعة وحدها، ثم رحلة متصفح محددة للتغييرات الحرجة. تفصل fixtures التحقق
اليدوي عن إثبات AI. عند الفشل يوثق الفشل وحدوده قبل الإصلاح ويُثبت الإصلاح
باختبار مستقل. لا تقاس الجودة بعدد الاختبارات الناجحة.

دراسة الفهم مستقلة: هل يميز المستخدم التنفيذ من النتيجة المثبتة، ويعرف
المشروع والقرار والخطوة التالية؟ لا نجاح UI آليًا يثبت هذا الفهم، ولا توضع
عتبات تحسن رقمية دون خط أساس.

## 11. غير المشمول وحالة التسليم

- لا بوابة إثبات جديدة ولا جدول لحالات العرض ولا مخزن قبول موازٍ.
- لا موافقة مباشرة من بطاقة عامة ولا تحويل تلقائي لكل محادثة إلى Mission.
- لا تشغيل استردادات أو تغيير مراحل العمل المعتمدة أو إعادة إصدار إيصالات.
- لا استبدال stack أو قواعد ملكية أو إعادة كتابة الصفحات بالكامل.
- لا ادعاء بإجراء اختبار حي أو بتحقق الأداء والإتاحة والفهم ضمن تحديث المستند.

**حالة التنفيذ الحالية:** بدأت شريحة من A وتصحيح أولوية الحالة وجزء تأكيد
مشروع الهدف من D. لا تزال عقود النتيجة والملخص المجمّع وإعادة تنظيم الصفحة
والعربية الشاملة وبقية المسودات مقترحة؛ لا يعني تنفيذ الأساس إغلاق A–G.

## 12. بدء التنفيذ: دليل الفشل قبل الإصلاح

بدأ تنفيذ الأساس بعد طلب البدء. أثبتت اختبارات مكونات مستقلة أن طلب قائمة
Tasks لا يحمل مشروعًا، وأن قائمة فارغة لا تستبدل القائمة المحتفظ بها،
وأن مراحل CHAT/INTAKE/READ/PLAN/BUILD/VALIDATE المحفوظة قد تخفي اكتمالًا
معروضًا من بيانات الإسقاط. هذه حدود مكونات وطلبات hooks؛ ليست دليل رحلة
حية أو إثباتًا لصلاحية قبول دائم. اختبار التحقق غير المتاح حافظ على الحجب.

الإصلاح لا يغير الخادم أو بوابات القبول، ولا يجعل إسقاط المكون Canonical Proof.

أثبت اختبار تسليم الهدف أن الإرسال لم يكن يتطلب تأكيد المشروع المختار
افتراضيًا. يضيف الإصلاح تأكيدًا محليًا لنطاق المشروع مع حارس داخل دالة
الإرسال، لا تعطيل زر فقط. لا يمنح التأكيد إذن Build أو موافقة على تغييرات.

### الشريحة المنفذة

- قائمة المهام ترسل مشروعًا مملوكًا ومفتاح استعلام يميز المشروع والفلاتر.
  لا تطلب قائمة بلا مشروع، وتتيح تغييره صراحة، ولا تختار بديلًا صامتًا
  لوجهة مشروع غير متاحة.
- الرابط إلى مهمة يحمّل المهمة المملوكة لتحديد مشروعها وإظهارها حتى لو كانت
  خارج صفحة القائمة الأولى. لا يُستخدم هذا لتعطيل ملكية API أو ربط القبول.
- نتيجة الاستعلام المعتمدة تستبدل القائمة عند الحذف أو الفراغ؛ أزيل احتفاظ
  Tasks بعلامة أحدث عنصر لأنها لا تمثل نسخة المجموعة. لم تُغيّر آلية
  watermark لبقية الصفحات ضمن هذه الشريحة.
- الاكتمال يتقدم على مرحلة تشغيل محفوظة، بعد حواجز الفشل والموافقة والإثبات
  الناقص والتسليم والمراجعة. هذا تصحيح عرض لا ترقية لقبول دائم.
- هدف الصفحة الرئيسية يتطلب تأكيد المشروع قبل الإرسال، ويعود الشرط عند
  تغيير المشروع. التأكيد لا يرسل الطلب، وحارس دالة الإرسال يغطي لوحة المفاتيح.
- إنشاء مهمة في مشروع آخر يختار مشروع المهمة الجديدة في القائمة بعد النجاح.

### دليل التحقق وحدوده

اجتازت اختبارات mission-state وExecutionProjectionPanel وTasks والمحادثة
المصادقة، وفحص TypeScript. تثبت ملكية نطاق العرض، وعزل مفاتيح المشروع،
واستبدال القائمة الفارغة، والوصول بالرابط، وأولوية الحالات والحفاظ على الحجب،
وعدم إرسال الهدف قبل التأكيد. لا تثبت Canonical Proof حقيقيًا أو استخدامًا
إنتاجيًا أو فهم مستخدم غير متخصص.

ظهر فشل لاختبار قديم لإرشاد حد الطلبات. أُعيد منفردًا وعلى نسخة مصدر معزولة
قبل التغييرات، وظهر الفشل نفسه؛ كان يتوقع نصًا سابقًا. صُحّحت assertions
لتثبت الإرشاد الحالي وغياب الإعادة التلقائية عند غياب وقت retry، مع الحفاظ
على فحوص التنقيح قبل إعادة فتح المحادثة وبعدها. لم يُغيّر سلوك المزود.

أعيد تشغيل Dashboard وظهر جاهزًا في سجل Vite. اللقطة غير المصادقة تعرض
صفحة الدخول العامة، فلا تُستخدم كإثبات للشاشات المحمية.

اجتاز فحص متصفح واحد في Firefox رحلة مصادقة ببيانات GET معزولة:
بقاء الهدف، منع الإرسال بـEnter قبل تأكيد المشروع، عدم إرسال الطلب عند
التأكيد، واشتراط تأكيد جديد عند تغيير المشروع. سجل اعتراض الطلبات صفر
طلبات AI. حملت طلبات المهام معرّفات المشاريع الصحيحة، واختفت صفوف المشروع
السابق عند الانتقال، ثم اختفت الصفوف بعد تحديث بقائمة فارغة.
لم تُنشأ سجلات backend ولم تحدث موافقة أو كتابة أو استرداد.

ظهرت مشكلة «Session history unavailable» وبعض أخطاء GET، ولم يكن المزود
متاحًا في المتصفح؛ لذلك لا يُنسب لهذا الفحص إثبات إرسال حي ناجح أو صحة
قائمة الجلسات. تغطي اختبارات المكونات الإرسال بعد التأكيد بمزود fixture.
لم ينفذ المتصفح حالة المشروع غير المتاح الاختيارية؛ يغطيها اختبار المكون.
هذه حدود دليل المتصفح وليست نجاحًا إنتاجيًا أو إغلاقًا لمشاكل غير مرتبطة.

المجمّع، العربية الشاملة، ودراسة الفهم ليست منجزة هنا. لم تُشغّل استردادات



# EPIC-AI-OR-01

## Title

**Dynamic OpenRouter Model Resolution & Free-Tier Optimization**

---

## Epic Goal

Remove hardcoded OpenRouter model selection and introduce a centralized, capability-driven model resolution policy with automatic fallback between supported free models.

---

## Scope

يشمل فقط:

* OpenRouter
* اختيار النموذج
* Free Tier
* Model Fallback
* Telemetry

ولا يشمل:

* Tool Policy
* Provider Registry redesign
* Retry Engine redesign
* AI orchestration redesign

---

# STORY-01

## Title

Extract OpenRouter Model Resolver

### Priority

P0

### Problem

Model identifiers are currently hardcoded inside execution paths.

Example:

```
chat-agent.ts

↓

fastModel
```

```
agent-complete.ts

↓

provider.defaultModels.powerful
```

This tightly couples execution logic to specific OpenRouter models.

---

### Files

```
lib/ai-orchestrator/src/provider-registry.ts

lib/ai-orchestrator/src/agents/chat-agent.ts

lib/ai-orchestrator/src/agent-complete.ts
```

New

```
lib/ai-orchestrator/src/openrouter/model-resolver.ts
```

---

### Tasks

Create

```
resolveModel()
```

Input

```
Capability

Quality

RequireTools

PreferFreeTier
```

Output

```
ResolvedModel
```

---

### Acceptance Criteria

* No execution component reads model IDs directly.
* All OpenRouter model selection goes through Model Resolver.
* Existing behavior preserved.

---

# STORY-02

## Title

Introduce Capability-Based Model Mapping

### Priority

P0

### Problem

Current routing is:

```
fast

↓

Gemma
```

```
power

↓

Llama
```

Instead it should become:

```
Capability

↓

Model
```

---

### Example Mapping

| Capability   | Target             |
| ------------ | ------------------ |
| Chat         | Lightweight Free   |
| Coding       | Code Model         |
| Tool Calling | Tool-capable Model |
| Reasoning    | High Capability    |
| JSON         | Structured-capable |
| Long Context | Long Context Model |

---

### Acceptance Criteria

Adding a new model requires updating only one mapping file.

---

# STORY-03

## Title

Automatic Free Model Fallback

### Priority

P0

### Problem

Current behavior:

```
Gemma

↓

404

↓

FAIL
```

Desired behavior:

```
Gemma

↓

404

↓

Llama

↓

DeepSeek

↓

Qwen

↓

FAIL
```

Only after all compatible free models fail.

---

### Files

```
model-resolver.ts

openrouter.strategy.ts
```

---

### Acceptance Criteria

404 on one model does not terminate the request.

---

# STORY-07

## Title

Registry Simplification

### Priority

P2

### Problem

Registry currently stores:

```
Provider

↓

Default Models
```

After introducing Model Resolver:

Registry should only describe providers.

---

### Files

```
provider-registry.ts
```

---

### Tasks

Keep only:

* Provider ID
* Endpoint
* Priority
* Authentication
* Provider capabilities

Remove:

```
defaultModels
```

---

### Acceptance Criteria

Provider Registry contains no routing logic.

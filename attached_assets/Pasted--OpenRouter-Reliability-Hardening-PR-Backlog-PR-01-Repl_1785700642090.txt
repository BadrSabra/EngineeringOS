# PR-01 — Replace Static OpenRouter Model Selection with Runtime Resolution

### Files

* `lib/ai-orchestrator/src/openrouter/model-catalog.ts`
* `lib/ai-orchestrator/src/provider-registry.ts`
* `lib/ai-orchestrator/src/openai-compatible-client.ts`
* `lib/ai-orchestrator/src/strategies/openrouter.strategy.ts`

### Problem

يستخدم النظام قائمة نماذج (Catalog) ثابتة لاختيار نموذج OpenRouter. عند إزالة نموذج أو تغييره أو انتقاله إلى خطة مدفوعة، يستمر النظام في اختياره مما يؤدي إلى:

* `MODEL_NOT_FOUND (404)`
* `selected model is unavailable`

### Evidence

* ظهور `MODEL_NOT_FOUND (404)` في Event Stream.
* `FREE_MODELS` معرفة داخل `model-catalog.ts`.
* `provider-registry.ts` يبني النماذج الافتراضية اعتمادًا على هذه القائمة.
* `openai-compatible-client.ts` يحاول نفس سلسلة النماذج الموجودة في الكتالوج.

### Acceptance Criteria

* إزالة أي Model IDs ثابتة قديمة.
* اختيار النموذج يتم من Catalog محدث أو Resolver ديناميكي.
* عدم إرسال أي Model ID غير موجود.
* اختبارات تغطي حذف نموذج من OpenRouter بدون كسر النظام.

# PR-02 — Strengthen OpenRouter Fallback Chain

### Files

* `lib/ai-orchestrator/src/openai-compatible-client.ts`
* `lib/ai-orchestrator/src/openrouter/model-resolver.ts`
* `lib/ai-orchestrator/src/provider-strategy.ts`

### Problem

عند فشل النموذج الحالي لا يتم التعافي بصورة كافية، وينتهي الطلب بخطأ رغم وجود بدائل محتملة.

### Evidence

* تكرار نفس الخطأ عدة مرات في Event Stream.
* انتهاء السلسلة برسالة:
  `All OpenRouter free-tier fallback models exhausted`
* عدم وجود انتقال واضح إلى Provider آخر في السيناريو الظاهر.

### Acceptance Criteria

* عند 404 أو MODEL_NOT_FOUND:

  * إزالة النموذج الفاشل من السلسلة.
  * تجربة النموذج التالي.
* عند انتهاء جميع نماذج OpenRouter:

  * الانتقال تلقائيًا إلى Provider آخر إذا كان متاحًا.
* تسجيل سبب كل انتقال في Logs.

# PR-03 — Improve Provider Failover

### Files

* `artifacts/api-server/src/lib/ai-route-helpers.ts`
* `lib/ai-orchestrator/src/provider-registry.ts`

### Problem

فشل OpenRouter يؤدي مباشرة إلى فشل العملية حتى عندما توجد Providers أخرى قابلة للاستخدام.

### Evidence

* `handleOrchestratorError()` يحول الخطأ إلى 422.
* `collectAvailableProviders()` يعتمد فقط على المفاتيح المتوفرة.
* لا يظهر Failover واضح في السيناريو الحالي.

### Acceptance Criteria

* تجربة Provider التالي تلقائيًا.
* عدم إعادة 422 إلا بعد استنفاد جميع Providers.
* تسجيل Provider الذي نجح في النهاية.

مع رسائل مناسبة لكل حالة.

لا يوجد آلية لعرض تقدم حي أو خطوات وسيطة أثناء تنفيذ المهمة.
النموذج ينتظر حتى يكتمل التنفيذ بالكامل ثم يعيد النتيجة النهائية مرة واحدة.

الوكيل يستخدم agentComplete() الذي يرسل طلبًا كاملًا إلى نموذج LLM ويتلقى استجابة واحدة.
لا يوجد دعم لتدفق الاستجابة (Streaming) أو إرسال تحديثات تقدم أثناء معالجة النموذج.
حتى في حالة استخدام نموذج يدعم التدفق، لا يتم استغلال هذه القدرة لعرض الخطوات الوسيطة.

Looking at the codebase, I can see the issue. The agent execution system has internal logging and step tracking, but these steps are not exposed to the user in a visible way during task execution.

Root Cause:

The ToolExecutionEngine.executeToolLoop() function in lib/ai-orchestrator/src/tool-execution-engine.ts manages the agentic tool loop and tracks steps internally, but these steps are only available through the onStep callback in the chat() function. When users execute tasks through the task agent, they don't see these intermediate steps.

Key Evidence:

BaseAgent.run() (base-agent.ts) - Handles single-shot LLM tasks with retry logic but doesn't expose intermediate steps
ToolExecutionEngine.executeToolLoop() (tool-execution-engine.ts) - Manages the full tool loop with iteration and tool call budgets, but steps are internal
chat() (chat-agent.ts) - Has an onStep callback for tracking steps, but this is only used in the chat interface, not in task execution
The Problem: When a user submits a task (like through the task agent), the system:

Executes the task through BaseAgent.run()
May call tools through ToolExecutionEngine.executeToolLoop()
Logs internal steps to console (as seen in the JSON.stringify warnings)
Returns only the final result
But the user never sees the intermediate steps like:

Which tools were called
What the model decided at each iteration
How many iterations were used
Why certain decisions were made
Solution: The chat() function already has the infrastructure to expose steps through the onStep callback. This needs to be:

Exposed in the task execution API
Connected to a user-facing progress indicator
Made available through the task agent interface
The fix would involve modifying the task agent to expose step tracking to the user, similar to how the chat interface already supports it through the onStep callback.

---
name: Episode and Execution lock order
description: Prevent row-lock cycles between accepted-proof readers and execution finalization.
---

Any transaction that needs both an Execution and its Episode must lock Execution before Episode. Resolve the Episode's execution identity with an unlocked read, then lock Execution and lock/revalidate the Episode. For linked episodes, first resolve the Mission/Goal identity without locks, then lock Mission before Goal before Execution, and finally lock/revalidate Episode. Episode event writes also insert a general event with `events.goal_id`; take the Goal key-share lock before Execution so the foreign-key check cannot wait on Goal while holding Execution. An Episode-only transaction must not later request the same Execution row. When a transaction also needs a World Transition row, lock Transition before Episode; an unlocked Episode identity read may select the matching transition first, then revalidate Episode under lock.

**Why:** Idempotent acceptance finalization holds Execution before closing an Episode, including an already accepted Episode. A concurrent proof reader that held Episode while waiting for Execution formed a reproducible PostgreSQL deadlock. Separately, an isolated interleaving reproduced `40P01` when Mission dependency proof held Episode before D2 Transition evaluation while the transition claimant held Transition before Episode. A controlled linked-event interleaving also reproduced `40P01` when the event insert's Goal foreign-key check waited on Goal after Execution was locked, while Mission finalization held Mission/Goal and waited on Execution.

**How to apply:** Use the shared pair-locking boundary for proof readers. For linked episode writes, reserve the Mission/Goal foreign-key identity before Execution, then keep Execution-before-Episode ordering; keep acceptance and evidence checks behind the Execution lock; and keep Transition-before-Episode where both rows are needed. Validate lock races only against a disposable PostgreSQL cluster. The reproductions establish these row-lock cycles, not production incidents.

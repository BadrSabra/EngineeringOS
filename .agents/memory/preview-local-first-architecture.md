نفّذ Preview بترتيب محلي ومحايد للمزود: خط أساس جنائي، ثم العقود، وLocal CAS، وBuilder مع Attestor، وRuntime/Gateway، وLocal Agent، ثم adapters اختيارية، وأخيرًا بوابة E2E كاملة. طبقات Control/Execution/Artifact/Trust/Delivery حدود منطقية، وليست خدمات أو قواعد بيانات إضافية.

**Why:** طلب المستخدم اعتماد التوسعات المعمارية مع الحفاظ على ترتيب local-first لتقليل مخاطر التراجع الأمني وتكرار الأنظمة. قواعد إثبات Candidate الحالية لا تتغير: Artifact Store يحفظ بايتات فقط، Builder ينفذ فقط، Attestor يثبت الناتج، والخادم القائم وحده يقرر القبول. تشغيل Attestor محليًا على جهاز يتحكم به مالكه لا يثبت استقلالًا بعيدًا؛ يجب الإفصاح عن مستوى الضمان وعدم مساواته بـremote/hardware attestation. استخدم Shared Evidence Graph/الإسقاط الحالي بدل Graph أو مصدر إثبات موازٍ.

**How to apply:** أكمل UXW-03.0 inventory قبل تغيير العقود؛ استخدم سياسة placement خادمية حتمية، Local أولًا، ولا تحويل Cloud صامتًا أو مدفوعًا. لا تجعل S3/ECS شرطًا للمسار الأساسي. أعد استخدام AWS كـadapter بعد تثبيت العقود، واجعل Cloudflare للنشر Static الاختياري لا للبناء/Attestation/Runtime. لا تنشئ جداول/مصادر إثبات موازية، ولا تنشر موارد cloud دون خطة تكلفة/موارد وموافقة منفصلة. لا تغلق UXW-03 قبل UXW-03.7 رحلة متصفح حقيقية وتعافيًا وعزلًا مثبتًا.

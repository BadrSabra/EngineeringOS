---
name: Preview build trust boundary
description: Security rules for compiling untrusted Candidate source into a static Preview artifact.
---

Candidate source is data, not a build authority. The initial profile is Vite/React static: the server selects one explicit relative `sourceRoot`, includes it in `sourceDigest`, and requires `index.html` there. The dependency allowlist is curated and pinned by the workspace lockfile. The Builder ignores Candidate Vite/PostCSS configuration, package scripts, and lockfiles; it runs one fixed Vite command and never installs Candidate dependencies. Before S3 access, it verifies an API-signed, short-lived Ed25519 job and derives all Candidate and artifact identities from its claims, not caller-supplied environment fields. It validates archive paths and every file digest, then creates a bounded static artifact and performs a conditional one-time write to the server-selected output key. Gateway-generated signed URLs and job tokens should not be placed directly in ECS `RunTask` overrides; pass only a narrowly scoped S3 environment-file ARN, and restrict its read permission to the Builder execution role.

**Why:** Vite configuration, package scripts, dependencies, and build output are all Candidate-controlled. Putting signing keys or cloud credentials in that process would turn ordinary source changes into privilege escalation. The project owner chose a server-selected root and preinstalled dependency allowlist instead of accepting Candidate build policy. ECS launch outcomes can be ambiguous when a response is lost; retrying with a new request can duplicate work, while refusing all retries can strand a valid build. Safe recovery therefore requires an exact fingerprint check, an immutable envelope, and the same ECS client token and parameters. Passing signed URLs as ECS environment values also places them in the control-plane request; an environment file keeps the values out of that request while allowing ECS to inject them at task start.

**How to apply:** Keep Builder execution, artifact attestation, Gateway control, and Preview serving as separate trust roles. The Gateway verifies the signed job, exact transfer URLs, fixed Task Definition and static public-key pin, then claims or resumes only an exact unexpired launch fingerprint. Store the environment file conditionally with that fingerprint as metadata, verify metadata before reusing its ARN, and repeat the same ECS request with the same client token. Give the ECS execution role read access only to that envelope prefix; do not add a task role, and keep the Builder subprocess environment allowlisted so untrusted build inputs cannot read the short-lived values. This only recovers an idempotent request; a background reconciler is still needed for expired or uncertain terminal jobs. The signed job and launch fence still do not prove the ECS image that ran or validate output, so require an independent attestor before accepting a receipt. Fail closed if the trusted build root or supported dependency profile is ambiguous; never fall back to running project commands.

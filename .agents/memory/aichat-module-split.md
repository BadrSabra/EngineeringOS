---
name: AiChat module split
description: How the dashboard AI chat page was split into modules and what remains in the main file
---
AiChat.tsx keeps the page component and re-exports the helpers the tests import; presentational components, parsers, and types live under pages/ai-chat/.

**Why:** the single file exceeded Babel's 500KB styling limit and mixed UI projections with stream ownership and send-preflight behavior.

**How to apply:** new helpers or cards go in the matching ai-chat module, not back into AiChat.tsx. The split was a mechanical move (no behavior edits), so verify later changes with the AiChat authenticated vitest file plus the Firefox release journey. Only type-only import cycles exist between types and live-activity; avoid adding value-level cycles. Self-contained effects/state already live in ai-chat/use-*.ts hooks (sessions drawer, execution audit, provider metrics, pending-changes persistence, cross-tab sync, and bounded live-activity state). Pure stream-error and stage-label presentation logic can move into its own module with output-contract tests. Typed presentation callbacks are isolated separately from session/execution lifecycle callbacks. Keep stream-generation fences on both groups. A reset callback may reconcile transient UI from durable status only when stream generation and execution ID match. Pure success/failure message projection and retention decisions may be isolated with invariant tests; keep the ownsStream decision, cache updates, terminal acceptance, and recovery actions in AiChat. Lifecycle callback helpers may apply execution/session identity only after that caller-owned fence passes and a live owner still exists. Send preflight remains an ordered pure decision that returns a reason; toasts and draft handoff stay in AiChat. Stream request context may normalize project/session/message and resume/build-plan fields after preflight, but stream generation, owner writes, and ownsStream stay in AiChat. The stream-start UI initializer may reset presentation state after the caller establishes ownership, but it must not rotate the generation or mutate stream ownership.

---
name: OpenRouter throttling and campaign checkpoints
description: Durable policy for model-scoped throttling, Retry-After waits, and empirical campaign persistence.
---

Model-scoped throttling must remain separate from the provider circuit. An OpenRouter 429 identified as an upstream shared-pool or credential/window limit must not trigger generic same-model retries, stream model advancement, or the tool loop's same-provider `powerModel` fallback. A shared-pool 429 cools only the exact failed model for 90 seconds in the current process; it is not a pool-wide or cross-instance quarantine. Provider Retry-After waits are opt-in, bounded by the request ledger, and must leave recovery reserve instead of consuming the full deadline.

**Why:** Provider-wide opening on one model's 429 unnecessarily removes healthy fallback candidates, while unbounded waiting caused live campaigns to outlast their request budget. The September 22, 2026 disposable run confirmed that OpenRouter candidates can independently return upstream shared-pool 429s even when catalog startup is healthy. September 30, 2026 project logs showed the generic transient retry replaying a shared-pool 429 against the same model and receiving a second 429; code-path review also found the outer tool loop could retry the same provider through `powerModel`.

**How to apply:** Classify the 429 once at the HTTP boundary where headers and provider metadata exist, carry only the bounded scope through health/telemetry, and let the Airlock or empirical campaign quarantine all remaining lanes/cases for a shared provider-pool hit. Shared-pool and credential limits must fail before generic transient retries, Retry-After replays, paid same-provider fallback, or the tool loop's same-provider model fallback. For shared-pool scope, cool only the exact failed OpenRouter model for 90 seconds in the current process; do not infer a model-to-upstream mapping or claim cross-instance isolation. Keep provider-credential limits separate because they apply beyond one model. Test default, explicitly disabled, and stream retry paths. Keep same-provider fallback ownership in the OpenRouter strategy/client, and route cross-provider recovery only through an existing caller-owned, authorized candidate list. Do not add a parallel retry chain or persistent pool quarantine; the existing provider circuit remains a separate policy. Preserve bounded probe candidate iteration only for model/capability failures, and persist empirical scorecards after every completed case. JSON repair must remain structural and bounded; schema validation stays authoritative.

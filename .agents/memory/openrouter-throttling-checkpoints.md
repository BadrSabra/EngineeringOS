---
name: OpenRouter throttling and campaign checkpoints
description: Durable policy for model-scoped throttling, Retry-After waits, and empirical campaign persistence.
---

Model-scoped throttling must remain separate from the provider circuit. An OpenRouter 429 identified as an upstream shared-pool or credential/window limit must not trigger generic same-model retries, stream model advancement, the tool loop's same-provider `powerModel` fallback, or the provider-wide circuit; rate limits and quota exhaustion are admission signals, not endpoint-health failures. A model cooldown is created only from a positive provider-supplied Retry-After, capped at six hours as a safety bound; missing or zero values create no local or durable cooldown, and repeated failures do not synthesize or escalate a delay. Legacy structured-task rows tagged with invented server/adaptive defaults are not live cooldown evidence. An opt-in wait must honor the full provider window only when it fits within the remaining request budget and recovery reserve; otherwise fail without sleeping or retrying early. A successful response clears that model's persisted cooldown. This is not a pool-wide quarantine and says nothing about other models' upstream routing.

**Why:** Provider-wide opening on one model's 429 unnecessarily removes healthy fallback candidates, while invented waits can block testing even when the provider supplies no Retry-After value. Process-local cooldowns also allow the next request routed to another API instance to hit the same throttled model. The September 22, 2026 disposable run confirmed that OpenRouter candidates can independently return upstream shared-pool 429s even when catalog startup is healthy. September 30, 2026 project logs showed the generic transient retry replaying a shared-pool 429 against the same model and receiving a second 429; code-path review also found the outer tool loop could retry the same provider through `powerModel`.

**How to apply:** Classify the 429 once at the HTTP boundary where headers and provider metadata exist, carry only the bounded scope through health/telemetry, and let the Airlock or empirical campaign quarantine all remaining lanes/cases for a shared provider-pool hit. Shared-pool and credential limits must fail before generic transient retries, Retry-After replays, paid same-provider fallback, or the tool loop's same-provider model fallback. For shared-pool scope, persist only a positive Retry-After for the exact failed OpenRouter model; on success, clear that model's persisted cooldown. Do not synthesize or exponentially escalate a duration when the provider omits Retry-After. Never truncate a longer provider wait and retry before the provider's deadline. Do not infer a model-to-upstream mapping or quarantine other model IDs. Keep provider-credential limits separate because they apply beyond one model. Retain a process-local cache only as a best-effort fallback if the shared store is unavailable. Test exact provider durations, missing/zero headers, waits beyond the caller budget, success clearing, and stream paths. Keep same-provider fallback ownership in the OpenRouter strategy/client, and route cross-provider recovery only through an existing caller-owned, authorized candidate list. Do not add a parallel retry chain or persistent pool quarantine; the existing provider circuit remains a separate policy. Preserve bounded probe candidate iteration only for model/capability failures, and persist empirical scorecards after every completed case. JSON repair must remain structural and bounded; schema validation stays authoritative.

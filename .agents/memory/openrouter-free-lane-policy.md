---
name: OpenRouter free-only routing
description: Product-level constraint for model selection, fallback, and rate-limit behavior.
---

The long-term product goal is zero paid AI API calls, with proof-bound pause/resume when no eligible free route exists. Current product routing remains OpenRouter-free-only; enabling another cloud or local route requires its own verified eligibility, capability, privacy, and operational gates. Paid and unknown-cost routes must fail closed.

Before each OpenRouter inference, enforce free-model capability and cooldown eligibility, then acquire bounded shared leases in order for a hashed credential identity, the catalog publisher namespace, and the exact model. Release in reverse order; if shared persistence or a lease is unavailable, do not send. The publisher namespace is only a conservative local concurrency lane, not evidence of OpenRouter's actual upstream quota group. Never persist or log the raw credential.

At the actual inference boundary, a static `FREE_MODELS` entry is only an eligible candidate, not proof of current price. Require a usable live catalog snapshot that lists the exact model with zero prompt and completion prices; otherwise stop before sending. Bound catalog refreshes, back off briefly after failure, and let a cancelled caller detach without aborting the shared refresh used by other requests.

API workers share the catalog through a PostgreSQL snapshot row and a token-fenced refresh lease. Persist only normalized catalog/model capability data and safe failure codes, never raw provider payloads or credentials. Re-read after lease acquisition; if another worker owns it, or the shared store cannot be read or written, do not fetch a second catalog or use uncommitted data. This coordinates `/models` refreshes and failure backoff across workers; it does not reveal or reserve OpenRouter's upstream inference quota. The API schema gate requires the snapshot table before startup.

429 and QUOTA end the current operation's model advancement. A positive provider `Retry-After` is retained separately for the reported, mappable scope; the effective `retryAfterMs` may be longer after a repeated mapped shared-pool 429, when a bounded local adaptive hold (30 seconds, doubling to 10 minutes) is added only after the provider window expires and a new 429 occurs. This local hold is backpressure, not an upstream recovery estimate. Persist and rehydrate adaptive shared-pool state across processes, and clear its repeat history after a successful response in that publisher namespace. Unknown or unmappable scope fails closed at credential scope. Without `Retry-After`, apply the same bounded local adaptive cooldown. Cross-process credential cooldown persistence requires the encryption key; without it, do not claim that this cooldown is shared. `EMPTY_RESPONSE` is a distinct contract/availability failure and may advance only to one additional eligible free model under the same task contract. Neither provider text nor cached output is acceptance proof.

**Why:** Cloud free quotas are shared, opaque, and provider-owned; application-local scheduling cannot guarantee availability or know the remaining quota. A short provider `Retry-After` can expire while the shared pool remains limited, so repeated 429s justify slowing this application's next eligible request without rewriting the original hint or claiming to know when quota recovers. Treating catalog ownership as proof of upstream routing, or an AI response as task proof, would create false guarantees.

**Why current-price admission matters:** the provider's model ID or `:free` suffix is not an immutable price contract. A fresh zero-price snapshot is the strongest local evidence available, but it cannot make a promise atomic with the provider's subsequent billing decision.

**How to apply:** keep the free-only authorization at the real send boundary as well as high-level entrypoints. Reject a non-product provider at the HTTP credential route before calling any validator; validation is not authorization and must not be the only barrier against network probes or credential persistence. Preserve the reported 429 scope; unknown scope means stop, not model roulette. Never retry the same operation after 429 or fall through to a paid/unknown route. Resume after exhaustion only through a durable, proof-bound task checkpoint that reuses accepted evidence and does not replay completed effects; this lifecycle still needs independent tests before claiming completion. In lifecycle integration tests, enter through the product's allowed OpenRouter route; mock strategy calls for durable task behavior, but test free-model identity separately before mocking away the model resolver. Provider registrations and secrets are configuration, not permission. Status reads remain local; do not log prompts, credentials, project IDs, or user identity in scheduler state.

**How to apply current-price checks:** every stream and non-stream transport path must check the fresh zero-price snapshot immediately before inference. Keep static fallback useful for planning only; do not weaken send admission to preserve old tests. Do not claim zero cost is guaranteed if the provider changes pricing between catalog observation and request acceptance.

**Why this testing boundary matters:** provider selection and model resolution occur before a mocked strategy. An excluded provider fixture can fail before the injected error, while the strategy mock cannot prove which model would have been sent.

---
name: OpenRouter free-only routing
description: Product-level constraint for model selection, fallback, and rate-limit behavior.
---

The long-term product goal is zero paid AI API calls, with proof-bound pause/resume when no eligible free route exists. Current product routing remains OpenRouter-free-only; enabling another cloud or local route requires its own verified eligibility, capability, privacy, and operational gates. Paid and unknown-cost routes must fail closed.

Before each OpenRouter inference, enforce free-model capability and cooldown eligibility, then acquire bounded shared leases in order for a hashed credential identity, the catalog publisher namespace, and the exact model. Release in reverse order; if shared persistence or a lease is unavailable, do not send. The publisher namespace is only a conservative local concurrency lane, not evidence of OpenRouter's actual upstream quota group. Never persist or log the raw credential.

429 and QUOTA end the current operation's model advancement. A positive provider `Retry-After` is retained only for the reported, mappable scope; unknown or unmappable scope fails closed at credential scope. Without `Retry-After`, apply bounded local adaptive cooldown (30 seconds, doubling to 10 minutes after recent repeats); this is backpressure, not an upstream recovery estimate. Cross-process credential cooldown persistence requires the encryption key; without it, do not claim that this cooldown is shared. `EMPTY_RESPONSE` is a distinct contract/availability failure and may advance only to one additional eligible free model under the same task contract. Neither provider text nor cached output is acceptance proof.

**Why:** Cloud free quotas are shared, opaque, and provider-owned; application-local scheduling cannot guarantee availability or know the remaining quota. Local leases can only prevent concurrency the application controls. Treating catalog ownership as proof of upstream routing, or treating an AI response as task proof, would create false guarantees.

**How to apply:** keep the free-only authorization at the real send boundary as well as high-level entrypoints. Reject a non-product provider at the HTTP credential route before calling any validator; validation is not authorization and must not be the only barrier against network probes or credential persistence. Preserve the reported 429 scope; unknown scope means stop, not model roulette. Never retry the same operation after 429 or fall through to a paid/unknown route. Resume after exhaustion only through a durable, proof-bound task checkpoint that reuses accepted evidence and does not replay completed effects; this lifecycle still needs independent tests before claiming completion. In lifecycle integration tests, enter through the product's allowed OpenRouter route; mock strategy calls for durable task behavior, but test free-model identity separately before mocking away the model resolver. Provider registrations and secrets are configuration, not permission. Status reads remain local; do not log prompts, credentials, project IDs, or user identity in scheduler state.

**Why this testing boundary matters:** provider selection and model resolution occur before a mocked strategy. An excluded provider fixture can fail before the injected error, while the strategy mock cannot prove which model would have been sent.
